## Dev Server Per Worktree

Each worktree runs its own dev server on a deterministic port. The `hash_port` filter generates a stable port (10000-19999) from the branch name. — [011-tips-patterns.md](worktrunk-guide-raw/011-tips-patterns.md)

### Configuration

```toml
# .config/wt.toml
[post-start]
server = "npm run dev -- --port {{ branch | hash_port }}"

[list]
url = "http://localhost:{{ branch | hash_port }}"

[pre-remove]
server = "lsof -ti :{{ branch | hash_port }} -sTCP:LISTEN | xargs kill 2>/dev/null || true"
```

The URL column in `wt list` shows each worktree's dev server, dimmed if not running. Ports are deterministic — `fix-auth` always gets port 16460 regardless of machine or timing. — [011-tips-patterns.md](worktrunk-guide-raw/011-tips-patterns.md)

## Database Per Worktree

Each worktree can have its own isolated database. A pipeline sets up names and ports as vars, then later steps reference them. — [011-tips-patterns.md](worktrunk-guide-raw/011-tips-patterns.md)

### Configuration

```toml
[[post-start]]
set-vars = """
wt config state vars set \
  container='{{ repo }}-{{ branch | sanitize }}-postgres' \
  port='{{ ('db-' ~ branch) | hash_port }}' \
  db_url='postgres://postgres:dev@localhost:{{ ('db-' ~ branch) | hash_port }}/{{ branch | sanitize_db }}'
"""

[[post-start]]
db = """
docker run -d --rm \
  --name {{ vars.container }} \
  -p {{ vars.port }}:5432 \
  -e POSTGRES_DB={{ branch | sanitize_db }} \
  -e POSTGRES_PASSWORD=dev \
  postgres:16
"""

[pre-remove]
db-stop = "docker stop {{ vars.container }} 2>/dev/null || true"
```

First step derives values from branch and stores as vars. Second step references `{{ vars.container }}` and `{{ vars.port }}`. `post-remove` reads same vars to stop container. — [011-tips-patterns.md](worktrunk-guide-raw/011-tips-patterns.md)

The `('db-' ~ branch)` concatenation hashes differently than plain `branch`, so database and dev server ports don't collide.

### Use Connection String

```bash
DATABASE_URL=$(wt config state vars get db_url) npm start
```

## Eliminate Cold Starts

Use `wt step copy-ignored` to copy gitignored files (caches, dependencies, `.env`) between worktrees. — [011-tips-patterns.md](worktrunk-guide-raw/011-tips-patterns.md)

### Configuration

```toml
[post-start]
copy = "wt step copy-ignored"
```

When another hook depends on the copy, sequence with a pipeline:

```toml
[[post-start]]
copy = "wt step copy-ignored"

[[post-start]]
install = "pnpm install"
```

Use `pre-start` instead when `--execute` command needs copied files immediately. — [011-tips-patterns.md](worktrunk-guide-raw/011-tips-patterns.md)

## Progressive Validation

Split checks across hook types — quick feedback before each commit, expensive suites before merge. — [011-tips-patterns.md](worktrunk-guide-raw/011-tips-patterns.md)

### Configuration

```toml
[[pre-commit]]
lint = "npm run lint"
typecheck = "npm run typecheck"

[[pre-merge]]
test = "npm test"
build = "npm run build"
```

`pre-commit` runs on every squash commit during `wt merge`; `pre-merge` runs once per merge after rebase.

## Target-Specific Hooks

Branch on `{{ target }}` to vary behavior per merge destination. — [011-tips-patterns.md](worktrunk-guide-raw/011-tips-patterns.md)

### Configuration

```toml
post-merge = """
if [ {{ target }} = main ]; then
    npm run deploy:production
elif [ {{ target }} = staging ]; then
    npm run deploy:staging
fi
"""
```

`{{ target }}` is the branch being merged into. `post-merge` runs in target's worktree (or primary worktree if target has none).

## Agent Handoffs

Spawn a worktree with an agent CLI running in the background. — [011-tips-patterns.md](worktrunk-guide-raw/011-tips-patterns.md)

### tmux (detached session)

```bash
tmux new-session -d -s fix-auth-bug "wt switch --create fix-auth-bug -x claude -- \
  'The login session expires after 5 minutes. Find and extend the timeout.'"
```

### Zellij (new pane)

```bash
zellij run -- wt switch --create fix-auth-bug -x claude -- \
  'The login session expires after 5 minutes. Find and extend the timeout.'
```

### cmux (new workspace)

```bash
cmux new-workspace --command "wt switch --create fix-auth-bug -x claude -- \
  'The login session expires after 5 minutes. Find and extend the timeout.'"
```

This lets one agent session hand off work to another running in background. Hooks run inside the multiplexer session/pane. — [011-tips-patterns.md](worktrunk-guide-raw/011-tips-patterns.md)

## Tmux Session Per Worktree

Each worktree gets its own tmux session with multi-pane layout. — [011-tips-patterns.md](worktrunk-guide-raw/011-tips-patterns.md)

### Configuration

```toml
# .config/wt.toml
[pre-start]
tmux = """
S={{ branch | sanitize }}
W={{ worktree_path }}
tmux new-session -d -s "$S" -c "$W" -n dev

# Create 4-pane layout
tmux split-window -h -t "$S:dev" -c "$W"
tmux split-window -v -t "$S:dev.0" -c "$W"
tmux split-window -v -t "$S:dev.2" -c "$W"

# Start services
tmux send-keys -t "$S:dev.1" 'npm run backend' Enter
tmux send-keys -t "$S:dev.2" 'claude' Enter
tmux send-keys -t "$S:dev.3" 'npm run frontend' Enter

tmux select-pane -t "$S:dev.0"
"""

[pre-remove]
tmux = "tmux kill-session -t {{ branch | sanitize }} 2>/dev/null || true"
```

Create and attach:

```bash
wt switch --create feature -x 'tmux attach -t {{ branch | sanitize }}'
```

## Shell Alias for New Worktree + Agent

Create a worktree and launch Claude in one command: — [011-tips-patterns.md](worktrunk-guide-raw/011-tips-patterns.md)

```bash
alias wsc='wt switch --create --execute=claude'
wsc new-feature                       # Creates worktree, runs hooks, launches Claude
wsc feature -- 'Fix GH #322'          # Runs `claude 'Fix GH #322'`
```

## Subdomain Routing with Caddy

Clean URLs like `http://feature-auth.myproject.localhost` without port numbers. — [011-tips-patterns.md](worktrunk-guide-raw/011-tips-patterns.md)

### Prerequisites

[Caddy](https://caddyserver.com/docs/install) (`brew install caddy`)

### Configuration

```toml
# .config/wt.toml
[post-start]
server = "npm run dev -- --port {{ branch | hash_port }}"
proxy = """
  curl -sf --max-time 0.5 http://localhost:2019/config/ || caddy start
  curl -sf http://localhost:2019/config/apps/http/servers/wt || \
    curl -sfX PUT http://localhost:2019/config/apps/http/servers/wt -H 'Content-Type: application/json' \
      -d '{"listen":[":8080"],"automatic_https":{"disable":true},"routes":[]}'
  curl -sf -X DELETE http://localhost:2019/id/wt:{{ repo }}:{{ branch | sanitize }} || true
  curl -sfX PUT http://localhost:2019/config/apps/http/servers/wt/routes/0 -H 'Content-Type: application/json' \
    -d '{"@id":"wt:{{ repo }}:{{ branch | sanitize }}","match":[{"host":["{{ branch | sanitize }}.{{ repo }}.localhost"]}],"handle":[{"handler":"reverse_proxy","upstreams":[{"dial":"127.0.0.1:{{ branch | hash_port }}"}]}]}'
"""

[pre-remove]
proxy = "curl -sf -X DELETE http://localhost:2019/id/wt:{{ repo }}:{{ branch | sanitize }} || true"

[list]
url = "http://{{ branch | sanitize }}.{{ repo }}.localhost:8080"
```

## FAQ

### Worktrunk vs Plain `git worktree`

Git's built-in commands work but require manual lifecycle management. Worktrunk automates the full lifecycle. — [012-faq.md](worktrunk-guide-raw/012-faq.md)

What `git worktree` doesn't provide:
- Consistent directory naming and cleanup validation
- Project-specific automation (install dependencies, start services)
- Unified status across all worktrees (commits, CI, conflicts, changes)

### Shell Integration Issues

If shell integration isn't working, use Claude Code with the Worktrunk plugin to debug: — [012-faq.md](worktrunk-guide-raw/012-faq.md)

1. Install the Worktrunk plugin
2. Ask Claude to debug the Worktrunk shell integration

Claude will run `wt config show`, inspect shell config files, and identify the issue.

### Files Worktrunk Creates

| Category | Location |
|----------|----------|
| Worktree directories | Configured via `worktree-path` |
| User config | `~/.config/worktrunk/config.toml` |
| Project config | `.config/wt.toml` |
| Approvals | `~/.config/worktrunk/approvals.toml` |
| Metadata/cache | `.git/wt/` |

— [012-faq.md](worktrunk-guide-raw/012-faq.md)

### What Can Be Deleted

- `wt remove` — refuses to remove worktrees with uncommitted changes (use `--force` for untracked files)
- `git worktree lock` — protects worktrees with precious data
- `-D` flag — force-deletes branches with unmerged changes
- `--no-delete-branch` — keeps branch regardless of status

— [012-faq.md](worktrunk-guide-raw/012-faq.md)

### Windows Support

Core commands, shell integration, and tab completion work in Git Bash and PowerShell. — [012-faq.md](worktrunk-guide-raw/012-faq.md)

- **Git for Windows required** — Hooks use bash syntax
- **`wt switch` interactive picker unavailable** — Uses skim which doesn't support Windows. Use `wt list` and `wt switch <branch>` instead.

### Default Branch Detection

Detection order: — [012-faq.md](worktrunk-guide-raw/012-faq.md)

1. Worktrunk cache (`git config worktrunk.default-branch`)
2. Git cache (primary remote HEAD)
3. Remote query (`git ls-remote`)
4. Local inference (branch heuristics)

If remote's default branch changed, clear cache: `wt config state default-branch clear`

### Installation C Compilation Errors

Install without syntax highlighting: — [012-faq.md](worktrunk-guide-raw/012-faq.md)

```bash
cargo install worktrunk --no-default-features --features cli
```

Disables bash syntax highlighting in output but keeps all core functionality.

## Hooks

Hooks are shell commands that run at key points in the worktree lifecycle. Ten hooks cover five events. — [007-hook.md](worktrunk-guide-raw/007-hook.md)

### Hook Types

| Event | `pre-` (blocking) | `post-` (background) |
|-------|-------------------|----------------------|
| switch | `pre-switch` | `post-switch` |
| start | `pre-start` | `post-start` |
| commit | `pre-commit` | `post-commit` |
| merge | `pre-merge` | `post-merge` |
| remove | `pre-remove` | `post-remove` |

`pre-*` hooks block — failure aborts the operation. `post-*` hooks run in background with output logged. — [007-hook.md](worktrunk-guide-raw/007-hook.md)

### Hook Purpose

| Hook | Purpose |
|------|---------|
| `pre-switch` | Before branch resolution or worktree creation |
| `post-switch` | All switch results: creating, switching, staying |
| `pre-start` | New worktree setup (blocking): dependency install, env generation |
| `post-start` | New worktree background tasks: dev servers, builds, file watchers |
| `pre-commit` | Formatters, linters during merge before squash commit |
| `post-commit` | CI triggers, notifications |
| `pre-merge` | Tests, security scans after rebase, before merge |
| `post-merge` | Deployment, notifications (runs in target worktree) |
| `pre-remove` | Cleanup before deletion (runs in worktree being removed) |
| `post-remove` | Stop servers, remove containers (variables reference removed worktree) |

— [007-hook.md](worktrunk-guide-raw/007-hook.md)

### Configuration Forms

**String** — single command:

```toml
pre-start = "npm install"
```

**Table** — multiple concurrent commands:

```toml
[post-start]
server = "npm run dev"
watch = "npm run watch"
```

**Pipeline** — sequential blocks, concurrent within each:

```toml
[[post-start]]
install = "npm ci"

[[post-start]]
build = "npm run build"
server = "npm run dev"
```

In the pipeline, `install` runs first, then `build` and `server` run together. — [007-hook.md](worktrunk-guide-raw/007-hook.md)

### Project vs User Hooks

| Aspect | Project Hooks | User Hooks |
|--------|--------------|------------|
| Location | `.config/wt.toml` | `~/.config/worktrunk/config.toml` |
| Scope | Single repository | All repositories |
| Approval | Required | Not required |
| Execution order | After user hooks | First |

— [007-hook.md](worktrunk-guide-raw/007-hook.md)

### Security

Project commands require approval on first run. Approvals saved to `~/.config/worktrunk/approvals.toml`. Use `--yes` to bypass prompts in CI. Use `--no-hooks` to skip hooks. — [007-hook.md](worktrunk-guide-raw/007-hook.md)

## Template Variables

Hooks can use template variables that expand at runtime. — [007-hook.md](worktrunk-guide-raw/007-hook.md)

### Active Variables

| Variable | Description |
|----------|-------------|
| `{{ branch }}` | Branch name |
| `{{ worktree_path }}` | Worktree directory path |
| `{{ worktree_name }}` | Worktree directory name |
| `{{ commit }}` | Branch HEAD SHA |
| `{{ short_commit }}` | Abbreviated SHA |
| `{{ upstream }}` | Branch upstream (if tracking) |

| Variable | Description |
|----------|-------------|
| `{{ base }}` | Base branch name |

| `{{ target }}` | Target branch name |
| `{{ target_worktree_path }}` | Target worktree path |

| Variable | Description |
|----------|-------------|

| `{{ default_branch }}` | Default branch name |
| `{{ remote }}` | Primary remote name |
| `{{ remote_url }}` | Remote URL |

### User Variables

| Variable | Description |
|----------|-------------|
| `{{ vars.<key> }}` | Per-branch variables from `wt config state vars` |

### Variable Perspective

| Operation | Bare vars | `base` | `target` |
|-----------|-----------|--------|----------|
| switch/create | destination | where you came from | = bare vars |
| merge | feature being merged | = bare vars | merge target |
| remove | branch being removed | = bare vars | where you end up |

## Template Filters

| Filter | Example | Description |
|--------|---------|-------------|
| `sanitize` | `{{ branch \| sanitize }}` | Replace `/` and `\` with `-` |
| `sanitize_db` | `{{ branch \| sanitize_db }}` | Database-safe: lowercase, underscores, hash suffix |
| `sanitize_hash` | `{{ branch \| sanitize_hash }}` | Filesystem-safe with hash suffix |
| `hash` | `{{ branch \| hash }}` | 3-character base36 digest |
| `hash_port` | `{{ branch \| hash_port }}` | Port 10000-19999 from hash |
| `dirname` | `{{ repo_path \| dirname }}` | Strip last path component |
| `basename` | `{{ repo_path \| basename }}` | Keep only last component |
| `codename(n)` | `{{ branch \| codename(2) }}` | Deterministic friendly name (adjective-noun) |

— [007-hook.md](worktrunk-guide-raw/007-hook.md)

### hash_port Usage

```toml
[post-start]
dev = "npm run dev -- --port {{ branch | hash_port }}"
```

Hash any string for unique ports:

```toml
dev = "npm run dev --port {{ (repo ~ '-' ~ branch) | hash_port }}"
```

— [007-hook.md](worktrunk-guide-raw/007-hook.md)

## Running Hooks Manually

`wt hook <type>` runs hooks on demand for testing, CI, or re-running after failure. — [007-hook.md](worktrunk-guide-raw/007-hook.md)

### Syntax

```bash
wt hook <TYPE> [NAMES...] [-- KEY=VALUE...] [-- ARGS...]
```

### Practical Examples

```bash
wt hook pre-merge              # Run all pre-merge hooks
wt hook pre-merge test         # Run hooks named "test"
wt hook pre-merge test build   # Run hooks named "test" and "build"
wt hook pre-merge user:        # Run all user hooks
wt hook pre-merge project:     # Run all project hooks
wt hook pre-merge user:test    # Run only user's "test" hook
wt hook pre-merge --yes        # Skip approval prompts
wt hook pre-start --branch=feature/test    # Override template variable
wt hook pre-merge -- --extra args          # Forward tokens into {{ args }}
```

## Aliases

Aliases define commands invoked as `wt <name>`. — [008-extending.md](worktrunk-guide-raw/008-extending.md)

### Configuration

```toml
[aliases]
deploy = "fly deploy --config=fly.{{ env }}.toml --app=myapp-{{ branch }}"
open = "open http://localhost:{{ branch | hash_port }}"
since-main = "git log --oneline {{ default_branch }}..HEAD"
```

### Invocation

```bash
wt deploy --env=staging
wt open
```

Resolution order: built-in → alias → custom subcommand. — [008-extending.md](worktrunk-guide-raw/008-extending.md)

### Template Variables

Aliases use same template engine as hooks. Additional variable: `{{ args }}` for positional arguments. — [008-extending.md](worktrunk-guide-raw/008-extending.md)

### Multi-step Pipelines

```toml
[[aliases.release]]
test = "cargo test"

[[aliases.release]]
build = "cargo build --release"
package = "cargo package --no-verify"

[[aliases.release]]
publish = "cargo publish {{ args }}"
```

Blocks run in order, keys within block run concurrently. — [008-extending.md](worktrunk-guide-raw/008-extending.md)

### Inspection

```bash
wt config alias show <name>        # Show template
wt config alias dry-run <name>     # Preview expanded command
wt config alias dry-run deploy -- --env=staging
```

— [008-extending.md](worktrunk-guide-raw/008-extending.md)

## Custom Subcommands

Any executable named `wt-<name>` on PATH becomes available as `wt <name>`. Built-ins and aliases take precedence. — [008-extending.md](worktrunk-guide-raw/008-extending.md)

### Example

```bash
# Install worktrunk-sync
cargo install worktrunk-sync

# Use as subcommand
wt sync origin
```

Arguments pass through verbatim, stdio inherited, exit code propagated. No template variables.

## Extension Comparison

| | Hooks | Aliases | Custom Subcommands |
|---|---|---|---|
| **Trigger** | Automatic (lifecycle) | Manual (`wt <name>`) | Manual (`wt <name>`) |
| **Defined in** | TOML config | TOML config | Any executable on PATH |
| **Template variables** | Yes | Yes | No |
| **Shareable via repo** | `.config/wt.toml` | `.config/wt.toml` | Distribute binary |
| **Language** | Shell commands | Shell commands | Any |

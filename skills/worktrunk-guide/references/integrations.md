## LLM Commit Messages

Worktrunk generates commit messages by building a templated prompt and piping it to an external command. Integrates with `wt merge`, `wt step commit`, and `wt step squash`. — [009-llm-commits.md](worktrunk-guide-raw/009-llm-commits.md)

### Setup

Add to `~/.config/worktrunk/config.toml`:

#### Claude Code

```toml
[commit.generation]
command = "CLAUDECODE= MAX_THINKING_TOKENS=0 claude -p --no-session-persistence --model=haiku --tools='' --disable-slash-commands --setting-sources='' --system-prompt=''"
```

`CLAUDECODE=` unsets nesting guard so `claude -p` works from within a Claude Code session. `--no-session-persistence` prevents commit conversation from polluting `--continue`. — [009-llm-commits.md](worktrunk-guide-raw/009-llm-commits.md)

#### Codex

```toml
[commit.generation]
command = "codex exec -m gpt-5.1-codex-mini -c model_reasoning_effort='low' -c system_prompt='' --sandbox=read-only --json - | jq -sr '[.[] | select(.item.type? == \"agent_message\")] | last.item.text'"
```

Uses fast mini model with low reasoning effort. Requires `jq` for JSON parsing. — [009-llm-commits.md](worktrunk-guide-raw/009-llm-commits.md)

#### Other Tools

```toml
# OpenCode
command = "opencode run -m anthropic/claude-haiku-4.5 --variant fast"

# llm
command = "llm -m claude-haiku-4.5"

# aichat
command = "aichat -m claude:claude-haiku-4.5"
```

— [009-llm-commits.md](worktrunk-guide-raw/009-llm-commits.md)

### How It Works

When worktrunk needs a commit message, it builds a prompt from template and pipes to configured command via `sh -c`. Environment variables can be set inline. — [009-llm-commits.md](worktrunk-guide-raw/009-llm-commits.md)

### Template Variables

| Variable | Description |
|----------|-------------|
| `{{ git_diff }}` | Diff content (staged or combined for squash) |
| `{{ git_diff_stat }}` | Diff statistics |
| `{{ branch }}` | Current branch name |
| `{{ repo }}` | Repository name |
| `{{ recent_commits }}` | Recent commit subjects (style reference) |
| `{{ commits }}` | Commits being squashed (squash template only) |
| `{{ target_branch }}` | Merge target (squash template only) |

— [009-llm-commits.md](worktrunk-guide-raw/009-llm-commits.md)

### Custom Templates

Override defaults with inline templates:

```toml
[commit.generation]
command = "llm -m claude-haiku-4.5"

template = """
Write a commit message for this diff. One line, under 50 chars.

Branch: {{ branch }}
Diff:
{{ git_diff }}
"""

squash-template = """
Combine these {{ commits | length }} commits into one message:
{% for c in commits %}
- {{ c }}
{% endfor %}

Diff:
{{ git_diff }}
"""
```

— [009-llm-commits.md](worktrunk-guide-raw/009-llm-commits.md)

### Template Syntax

Templates use minijinja (Jinja2-like): — [009-llm-commits.md](worktrunk-guide-raw/009-llm-commits.md)

- **Variables**: `{{ branch }}`, `{{ repo | upper }}`
- **Filters**: `{{ commits | length }}`
- **Conditionals**: `{% if recent_commits %}...{% endif %}`
- **Loops**: `{% for c in commits %}{{ c }}{% endfor %}`
- **Whitespace control**: `{%- ... -%}` strips surrounding whitespace

### Branch Summaries

With `summary = true` and `[commit.generation]` configured, Worktrunk generates LLM branch summaries — one-line descriptions of each branch's changes since default branch. — [009-llm-commits.md](worktrunk-guide-raw/009-llm-commits.md)

Enable in user config:

```toml
[list]
summary = true
```

Summaries appear in:
- `wt switch` interactive picker — preview tab 5
- `wt list --full` — Summary column

Summaries cached until diff changes.

### Fallback Behavior

When no LLM configured, worktrunk generates deterministic messages based on changed filenames (e.g., "Changes to auth.rs & config.rs"). — [009-llm-commits.md](worktrunk-guide-raw/009-llm-commits.md)

## Claude Code Integration

The worktrunk Claude Code plugin provides configuration skill, worktree isolation, and activity tracking. — [010-claude-code.md](worktrunk-guide-raw/010-claude-code.md)

### Installation

Recommended:

```bash
wt config plugins claude install
```

Manual:

```bash
claude plugin marketplace add max-sixty/worktrunk
claude plugin install worktrunk@worktrunk
```

— [010-claude-code.md](worktrunk-guide-raw/010-claude-code.md)

### Configuration Skill

The plugin includes a skill — documentation that Claude Code can read — covering worktrunk's configuration system. Claude Code can help with: — [010-claude-code.md](worktrunk-guide-raw/010-claude-code.md)

- Setting up LLM-generated commit messages
- Adding project hooks (pre-start, pre-merge, pre-commit)
- Configuring worktree path templates
- Fixing shell integration issues

### Activity Tracking

Plugin tracks Claude sessions with status markers in `wt list`: — [010-claude-code.md](worktrunk-guide-raw/010-claude-code.md)

| Marker | Meaning |
|--------|---------|
| `🤖` | Claude is working |
| `💬` | Claude is waiting for input |

### Manual Markers

Set status markers for any workflow:

```bash
wt config state marker set "🚧"                   # Current branch
wt config state marker set "✅" --branch feature  # Specific branch
git config worktrunk.state.feature.marker '{"marker":"💬","set_at":0}'
```

— [010-claude-code.md](worktrunk-guide-raw/010-claude-code.md)

### Worktree Isolation

Claude Code agents can run in isolated worktrees (`isolation: "worktree"`). The plugin's `WorktreeCreate` and `WorktreeRemove` hooks route creation/removal through `wt switch --create` and `wt remove`, so worktrees get worktrunk's naming conventions, hooks, and lifecycle management. — [010-claude-code.md](worktrunk-guide-raw/010-claude-code.md)

### Statusline

`wt list statusline --format=claude-code` outputs single-line status for Claude Code statusline. When CI cache stale, fetches from network (1-2 seconds). — [010-claude-code.md](worktrunk-guide-raw/010-claude-code.md)

Add to `~/.claude/settings.json`:

```json
{
  "statusLine": {
    "type": "command",
    "command": "wt list statusline --format=claude-code"
  }
}
```

When Claude Code provides context window usage via stdin JSON, a moon phase gauge appears (full to new moon as context fills).

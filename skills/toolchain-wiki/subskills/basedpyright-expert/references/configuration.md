## Configuration Hierarchy

1. `pyrightconfig.json` (highest priority)
2. `[tool.basedpyright]` in `pyproject.toml`
3. `[tool.pyright]` in `pyproject.toml` (backwards compatibility)
4. Language server settings (lowest priority)

If a config file exists, discouraged language server settings are ignored.

## Config File: pyproject.toml

```toml
[tool.basedpyright]
include = ["src"]
exclude = ["**/node_modules", "**/__pycache__"]
pythonVersion = "3.12"
pythonPlatform = "All"
typeCheckingMode = "recommended"

# Basedpyright-exclusive settings
failOnWarnings = true
allowedUntypedLibraries = ["requests", "old_lib"]

# Override individual rules
reportMissingImports = "error"
reportMissingTypeStubs = "warning"
```

## Diagnostic Categories

| Category | CLI Behavior |
|----------|--------------|
| `error` | Exit code 1 |
| `warning` | Exit code 1 if `failOnWarnings=true` |
| `information` | Never fails CLI |
| `hint` | LSP only (greystrikethrough), not in CLI |
| `none` | Disabled |

Deprecated categories (`unreachable`, `unused`, `deprecated`) are aliases for `hint`.

## Type Checking Modes

| Mode | Description |
|------|-------------|
| `off` | No type checking, syntax errors only |
| `basic` | Minimal checking, no strict inference |
| `standard` | Default pyright behavior |
| `strict` | Most checks enabled |
| `recommended` | All checks as warning/error, failOnWarnings=true |

## Comments for Type Control

### File-Level Controls

```python
# pyright: strict
# pyright: basic
# pyright: strict, reportPrivateUsage=false
# pyright: reportPrivateUsage=warning, reportOptionalCall=error
```

### Line-Level Suppression

```python
x = some_func()  # pyright: ignore
x = some_func()  # pyright: ignore[reportUnknownVariableType]
```

**Prefer `# pyright: ignore` over `# type: ignore`:**
- `# type: ignore` suppresses all errors regardless of rule specified
- `# type: ignore` does not validate rule names
- `enableTypeIgnoreComments` is disabled by default in basedpyright

## LSP Settings

### VS Code / VSCodium

```json
{
  "basedpyright.analysis.diagnosticMode": "openFilesOnly",
  "basedpyright.analysis.configFilePath": "${workspaceFolder}/backend"
}
```

### Neovim 0.11+

```lua
return {
  settings = {
    basedpyright = {
      analysis = {
        diagnosticMode = "openFilesOnly",
        inlayHints = { callArgumentNames = true }
      }
    }
  }
}
```

## Baseline Configuration

### CLI Baseline Modes

| Mode | Behavior |
|------|----------|
| (not specified) | Local: auto, CI: lock |
| `--writebaseline` | Always update baseline |
| `--baselinemode=auto` | Update only when errors removed |
| `--baselinemode=lock` | Never update, exit non-zero if needs update |
| `--baselinemode=discard` | Read but never update |

## Discouraged Settings

| Setting | Reason | Alternative |
|---------|--------|-------------|
| `venvPath` / `venv` | Confusing configuration | Use `.venv` convention or `--pythonpath` |
| `enableTypeIgnoreComments` | Less safe than `# pyright: ignore` | Use `# pyright: ignore[ruleName]` |
| `enableReachabilityAnalysis` | Less flexible | Use `reportUnreachable` rule |

## Execution Environments

For monorepos with different Python versions or platforms per subdirectory:

```toml
[tool.basedpyright]
executionEnvironments = [
  { root = "backend", pythonVersion = "3.10", extraPaths = ["shared"] },
  { root = "frontend", pythonVersion = "3.12" }
]
```

Each environment can override: `pythonVersion`, `pythonPlatform`, `extraPaths`, and any diagnostic rule.

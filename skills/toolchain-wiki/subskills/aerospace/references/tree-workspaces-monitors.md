## Tree Model & Terminology

AeroSpace stores windows and containers in a per-workspace tree — [001-guide.md](aerospace-raw/001-guide.md):

- **Root node:** Every workspace owns one root container.
- **Containers:** Non-leaf nodes hold arbitrary child nodes with a `layout` (`tiles` or `accordion`) and an `orientation` (`horizontal` or `vertical`).
- **Windows:** Leaf nodes hold zero children. "Window layout" refers to its parent container's layout.
- **i3 terminology difference:** What i3 calls a "container" is a "node" in AeroSpace.

Change tree structure with `move`, `join-with`, or `split` (`join-with` is preferred when normalizations are enabled) — [001-guide.md](aerospace-raw/001-guide.md).

## Layouts

| Layout | Orientation | Behavior |
| --- | --- | --- |
| `h_tiles` | Horizontal | Places child nodes side-by-side — [001-guide.md](aerospace-raw/001-guide.md) |
| `v_tiles` | Vertical | Stacks child nodes top-to-bottom — [001-guide.md](aerospace-raw/001-guide.md) |
| `h_accordion` | Horizontal | Overlaps windows with left/right padding (`focus left` / `right`) — [001-guide.md](aerospace-raw/001-guide.md) |
| `v_accordion` | Vertical | Overlaps windows with top/bottom padding (`focus up` / `down`) — [001-guide.md](aerospace-raw/001-guide.md) |

Control accordion overlap width with `accordion-padding` (default `30`, `0` disables) — [default-config.toml](aerospace-raw/config-examples/default-config.toml).

## Tree Normalizations

Two automatic normalizations run by default so screen geometry matches the tree — [001-guide.md](aerospace-raw/001-guide.md):

1. **Flatten single-child containers (`enable-normalization-flatten-containers = true`):** Collapses non-root containers holding one child.
2. **Opposite orientation for nested containers (`enable-normalization-opposite-orientation-for-nested-containers = true`):** Flips a nested container to the opposite orientation of its parent (`h_tiles` inside `h_tiles` becomes `v_tiles` inside `h_tiles`).

```toml
# Disable normalizations only for strict i3 tree parity
enable-normalization-flatten-containers = false
enable-normalization-opposite-orientation-for-nested-containers = false
```

## Floating Windows & Dialog Heuristics

Floating windows live outside the tiling tree, except during `focus` — [001-guide.md](aerospace-raw/001-guide.md):

- **`focus` resolution:** Treats a floating window as a child of the smallest tiling container holding its center point. Pass `--ignore-floating` to skip floating windows.
- **Dialog heuristics:** macOS Accessibility APIs lack reliable dialog metadata across apps. AeroSpace auto-floats windows without a fullscreen button (excluding terminal emulators like WezTerm, Alacritty, and iTerm2) — [001-guide.md](aerospace-raw/001-guide.md).

Override dialog heuristics per app in `on-window-detected`:

```toml
on-window-detected = [
    { if = 'test %{app-bundle-id} = com.example.app', run = 'layout tiling' },
    { if = 'test %{app-bundle-id} = com.apple.finder', run = 'layout floating' },
]
```

## Virtual Workspaces & Monitor Arrangement

Native macOS Spaces impose a 16-space limit, slow animations, and no public API. AeroSpace emulates workspaces by moving inactive windows to a bottom corner of the screen — [001-guide.md](aerospace-raw/001-guide.md).

- **1-pixel recovery edge:** macOS forces at least 1 pixel onscreen, so windows remain recoverable by dragging if AeroSpace exits unexpectedly.
- **Monitor arrangement requirement:** Open `System Settings -> Displays -> Arrange...` and ensure every monitor has an exposed bottom-left or bottom-right corner. Overlapping bottom corners leak hidden windows onto adjacent displays — [001-guide.md](aerospace-raw/001-guide.md).
- **Clean shutdown:** Quitting AeroSpace returns all hidden windows to visible coordinates.

### Recommended macOS Settings

| Setting | Command / Path | Why |
| --- | --- | --- |
| Group windows by application | `defaults write com.apple.dock expose-group-apps -bool true && killall Dock` | Prevents Mission Control from shrinking corner-parked windows — [001-guide.md](aerospace-raw/001-guide.md) |
| Disable Displays have separate Spaces | `defaults write com.apple.spaces spans-displays -bool true && killall SystemUIServer` | Eliminates multi-monitor focus bugs and API stalls (requires logout) — [001-guide.md](aerospace-raw/001-guide.md) |

Trade-off when `Displays have separate Spaces` is disabled: native macOS fullscreen turns secondary displays black, and the menu bar renders only on the main monitor — [001-guide.md](aerospace-raw/001-guide.md).

## Multi-Monitor Model & Force Assignment

AeroSpace shares one workspace pool across monitors — [001-guide.md](aerospace-raw/001-guide.md):

- Each monitor displays one visible workspace at a time.
- Two monitors cannot show the same workspace simultaneously.
- Every workspace (even empty) belongs to a monitor (`main` by default). Switching to an empty workspace focuses its assigned monitor rather than pulling it to the active monitor like i3.

Force workspaces onto specific monitors using `[workspace-to-monitor-force-assignment]` — [001-guide.md](aerospace-raw/001-guide.md):

```toml
[workspace-to-monitor-force-assignment]
    1 = 1                             # 1-based monitor index (left to right)
    2 = 'main'                        # Main display in System Settings
    3 = 'secondary'                   # Non-main display in a 2-monitor setup
    4 = 'built-in'                    # Case-insensitive regex substring
    5 = '^built-in retina display$'   # Case-insensitive exact regex match
    6 = ['secondary', 'dell']         # First matching pattern wins
```

`move-workspace-to-monitor` fails on any workspace listed under `[workspace-to-monitor-force-assignment]` — [001-guide.md](aerospace-raw/001-guide.md), [002-commands.md](aerospace-raw/002-commands.md).

## Status Bars & Window Borders

### SketchyBar

#### Legacy `exec-on-workspace-change` Setup (Backward-Compatible)

Start SketchyBar in `after-startup-command` and notify it via `exec-on-workspace-change` — [003-goodies.md](aerospace-raw/003-goodies.md):

```toml
after-startup-command = ['exec-and-forget sketchybar']

exec-on-workspace-change = ['/bin/bash', '-c',
    'sketchybar --trigger aerospace_workspace_change FOCUSED_WORKSPACE=$AEROSPACE_FOCUSED_WORKSPACE'
]
```

Use `aerospace list-workspaces --all` to register workspace items and toggle `background.drawing` inside the plugin script when `$1 = $FOCUSED_WORKSPACE` — [003-goodies.md](aerospace-raw/003-goodies.md).

#### Modern `subscribe`-Based Event Bridge

For lower latency and zero per-switch `/bin/bash -c` spawns, run a single persistent listener over `aerospace subscribe` and batch SketchyBar updates or triggers from the JSONL stream:

```bash
#!/usr/bin/env bash
set -euo pipefail

PIDFILE="${TMPDIR:-/tmp}/sketchybar-aerospace-bridge.pid"
[ -f "$PIDFILE" ] && kill "$(cat "$PIDFILE")" 2>/dev/null || true
echo $$ > "$PIDFILE"
trap 'rm -f "$PIDFILE"' EXIT

while true; do
  aerospace subscribe focused-workspace-changed focused-monitor-changed mode-changed window-detected \
    | jq -r --unbuffered '[._event, (.workspace // ""), (.prevWorkspace // ""), (.monitorId // ""), (.mode // "")] | @tsv' \
    | while IFS=$'\t' read -r event ws prev mon mode; do
        case "$event" in
          focused-workspace-changed)
            sketchybar --trigger aerospace_workspace_change FOCUSED_WORKSPACE="$ws" PREV_WORKSPACE="$prev"
            ;;
          focused-monitor-changed)
            sketchybar --trigger aerospace_monitor_change FOCUSED_WORKSPACE="$ws" MONITOR_ID="$mon"
            ;;
          mode-changed)
            sketchybar --set aerospace.mode label="$mode"
            ;;
          window-detected)
            sketchybar --trigger aerospace_window_detected WORKSPACE="$ws"
            ;;
        esac
      done
  sleep 1
done
```

See [callbacks-scripting.md](callbacks-scripting.md) for full wire schemas, known `v0.21.3-Beta` event coverage gaps (`move-node-to-workspace`, `window-closed`, `move-workspace-to-monitor`) with workarounds, and reconnect/pidfile hygiene.

#### Multi-Monitor Display Ordering Caveat & Deterministic Fix

Monitor IDs differ across three macOS display orderings:

- **AeroSpace `%{monitor-id}` / `subscribe` `monitorId`:** 1-based geometric order (`monitors.sortedBy([\.rect.minX, \.rect.minY])`).
- **AeroSpace `%{monitor-appkit-nsscreen-screens-id}`:** 1-based index in AppKit `NSScreen.screens` (main monitor first, then AppKit/hardware order).
- **SketchyBar `display=<arrangement-id>`:** 1-based index from private SkyLight `SLSCopyManagedDisplays`, which frequently disagrees with `NSScreen.screens` on 3+ monitor setups.

Build a deterministic `<aerospace_monitor_id> -> <sketchybar_arrangement_id>` lookup directly from SketchyBar's own display geometry:

```bash
# Outputs "<aerospace_monitor_id> <sketchybar_arrangement_id>"
sketchybar --query displays | jq -r '
  sort_by(.frame.x, .frame.y)
  | to_entries[]
  | "\(.key + 1) \(.value["arrangement-id"])"
'
```

Refresh this mapping inside your listener or plugin whenever SketchyBar emits `display_change` (when displays are plugged, unplugged, or rearranged).

### simple-bar (Übersicht)

Refresh `simple-bar-index-jsx` from both `on-focus-changed` and `exec-on-workspace-change` — [003-goodies.md](aerospace-raw/003-goodies.md):

```toml
on-focus-changed = [
  "exec-and-forget osascript -e 'tell application id \"tracesOf.Uebersicht\" to refresh widget id \"simple-bar-index-jsx\"'",
]
exec-on-workspace-change = [
  '/bin/zsh', '-c',
  '/usr/bin/osascript -e "tell application id \"tracesOf.Uebersicht\" to refresh widget id \"simple-bar-index-jsx\""',
]
```

## Opening New Windows with AppleScript

`open -a Safari` focuses an existing Safari workspace instead of opening a window on the current workspace. Use AppleScript inside `[mode.main.binding]` — [003-goodies.md](aerospace-raw/003-goodies.md):

Note: `default-config.toml` shows a commented `alt-enter` example for Terminal instead of `ctrl-g`. Pick one app per binding key.

Safari:

```toml
[mode.main.binding]
    ctrl-g = '''exec-and-forget osascript -e '
tell application "Safari"
    make new document at end of documents
    activate
end tell'
'''
```

Terminal.app:

```toml
[mode.main.binding]
    ctrl-g = '''exec-and-forget osascript -e \
'tell application "Terminal" to tell (do script) to activate' '''
```

Ghostty:

```toml
[mode.main.binding]
    ctrl-g = '''exec-and-forget osascript -e '
tell application "Ghostty"
    new window
end tell'
'''
```

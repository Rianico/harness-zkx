## Dev server per worktree

Each worktree gets a stable port from `hash_port`. The dev server starts on `post-start` and stops on `pre-remove`.

```toml
# .config/wt.toml
[post-start]
server = "npm run dev -- --port {{ branch | hash_port }}"

[list]
url = "http://localhost:{{ branch | hash_port }}"

[pre-remove]
server = "lsof -ti :{{ branch | hash_port }} -sTCP:LISTEN | xargs kill 2>/dev/null || true"
```

`wt list` shows URL. The cell dims until the port answers.

## Database per worktree

Each worktree gets an isolated database. The hash_port gives a unique port per branch.

```toml
[post-start]
db = "docker run -d --name postgres-{{ branch | sanitize }} -p {{ ('pg-' ~ branch) | hash_port }}:5432 postgres:16"
# Different hash than dev server port

[pre-remove]
db = "docker rm -f postgres-{{ branch | sanitize }}"
```

Use `config set VAR` for connection strings:

```toml
[post-start]
env = "wt config state vars set DATABASE_URL=postgres://localhost:{{ ('pg-' ~ branch) | hash_port }}/{{ branch | sanitize_db }}"
```

## Cold-start elimination

New worktrees start from a blank filesystem. Copy caches and dependencies to avoid reinstalling.

### copy-ignored (recommended)

```toml
[post-start]
copy = "wt step copy-ignored"
```

Copies gitignored files from the main worktree. Uses reflink for speed. Control with `.worktreeinclude`.

### Warm-up hooks

Chain sequential hooks to install only what copy-ignored missed:

```toml
[[post-start]]
copy = "wt step copy-ignored"

[[post-start]]
deps = "npm ci"
build = "npm run build"
```

### Language-specific tips

| Stack  | Approach                                                                    |
| ------ | --------------------------------------------------------------------------- |
| Rust   | `wt step copy-ignored` copies `target/` — first build ~3 s instead of ~68 s |
| Node   | Symlink `node_modules` from primary worktree if no native deps            |
| Python | `uv sync` is faster than copying venvs (which contain absolute paths)     |

## Tmux integration

Launch a tmux session named after the branch on switch:

```bash
wt switch --create feat -x tmux -- new -s '{{ branch | sanitize }}'
```

Combine with aliases:

```toml
[aliases]
wstm = "switch --create -x tmux -- new -s '{{ branch | sanitize }}'"
```

## Agent-driven workflows

Agents use `--yes` to skip prompts. Use `--format=json` for structured output.

```bash
wt switch --create fix-bug -x claude -- 'Fix null pointer in handler'
wt list --format=json 2>/dev/null | jq '(.items // .)'
wt merge --yes
```

Use `wt for-each` to check status across all worktrees:

```bash
wt step for-each -- sh -c 'echo "{{ branch }}: $(git status --short | wc -l) changes"'
```

## FAQ

**Q: shell integration not working after install?**

Restart the shell. Verify `wt config shell install` completed. Check `.zshrc` or `.bashrc` for the worktrunk source line.

**Q: cold start slow?**

Add `[post-start] copy = "wt step copy-ignored"` to project config. Set up `.worktreeinclude` to list what to copy.

**Q: stale worktrees accumulating?**

Run `wt step prune --dry-run` to preview. Run `wt step prune` to remove all merged worktrees. The `--min-age` guard blocks deleting fresh worktrees.

**Q: two worktrees on the same branch?**

Allowed. Both show `⚑` in `wt list` (duplicate branch). Use a path argument to address a specific one.

**Q: path occupied by non-worktree?**

Use `--clobber` with `wt switch` to remove stale paths. Or delete manually and retry.

**Q: CI status not showing?**

Use `wt list --full`. Ensure `gh`, `glab`, or equivalent CLI is installed and authenticated.

**Q: LLM summaries not appearing?**

Set `[list] summary = true` and configure `[commit.generation]`. Requires `wt list --full`. Cached until the diff changes.

## Tells and smells

### Tells (signs of a healthy worktree workflow)

- `wt list` shows every branch with a worktree and status symbols are green.
- `wt step prune` shows zero or few stale worktrees.
- Dev servers auto-start on switch and stop on remove.
- CI column populated for active branches under `--full`.

### Smells (signs of problems)

- `wt list` shows many dimmed rows (safe to delete → prune them).
- `⚑` symbols accumulate (duplicate branch worktrees → consolidate).
- `✘` conflict symbols appear (mid-operation → resolve or abort).
- CI column blank on branches with PRs (missing `gh`/`glab` CLI or authentication).
- `wt switch` fails with path occupied (stale directory → `--clobber`).

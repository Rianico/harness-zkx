## Architecture Overview

Tauri uses a multi-process architecture that isolates web frontend rendering from operating system operations.

```
┌────────────────────────────────────────────────────────┐
│                   Core Process (Rust)                  │
│                                                        │
│  tauri::Builder ──> App / AppHandle ──> State / Plugins │
│           │                     │                      │
│      TAO (Windowing)       WRY (Webview)               │
└───────────┬─────────────────────┬──────────────────────┘
            │ IPC Messages        │ Native Events
┌───────────▼─────────────────────▼──────────────────────┐
│                  Webview Process                       │
│                                                        │
│   HTML / CSS / JavaScript UI (Vite, React, Svelte)     │
│   @tauri-apps/api/core (invoke)                        │
└────────────────────────────────────────────────────────┘
```

The architecture consists of two upstream libraries:
- **TAO**: Cross-platform application window creation library in Rust (fork of `winit`).
- **WRY**: Cross-platform webview rendering library in Rust. It drives WKWebView on macOS and iOS, WebView2 on Windows, and WebKitGTK on Linux.

## Process Model

Tauri separates duties between the core process and webview render processes.

| Process | Runtime | Responsibilities | Privileges |
| ------- | ------- | ---------------- | ---------- |
| **Core Process** | Rust | Window lifecycle, system tray, menus, file system, IPC dispatch, plugins | Full operating system access |
| **Webview Process** | Native Webview Engine | DOM rendering, user event handling, JavaScript UI execution | Sandboxed by operating system |

The core process exposes system capabilities through explicit IPC commands. The frontend never accesses operating system APIs directly.

## Application Bootstrap and Builder

The application initializes through `tauri::Builder` in `src-tauri/src/lib.rs`.

```rust
#[cfg_attr(mobile, tauri::mobile_entry_point)]
pub fn run() {
    tauri::Builder::default()
        .plugin(tauri_plugin_opener::init())
        .setup(|app| {
            // Setup hook runs before the event loop starts
            let handle = app.handle();
            println!("App initialized: {}", app.package_info().name);
            Ok(())
        })
        .run(tauri::generate_context!())
        .expect("error while running tauri application");
}
```

The `tauri::generate_context!()` macro reads `tauri.conf.json` at compile time. It embeds icons, application configuration, and system permissions into the binary.

## Lifecycle Hooks

Tauri provides lifecycle hooks on `tauri::Builder` to intercept application events.

| Hook | Signature | Purpose |
| ---- | --------- | ------- |
| `setup` | `FnOnce(&mut App) -> Result<(), Box<dyn Error>>` | Runs after window creation and plugin setup. Use to initialize state or spawn background tasks. |
| `on_window_event` | `Fn(&Window, &WindowEvent)` | Intercepts window events like focus changes, resizing, or close requests. |
| `on_webview_event` | `Fn(&Webview, &WebviewEvent)` | Intercepts webview lifecycle events like page navigation. |

### Intercepting Close Requests

Prevent immediate application exit on window close:

```rust
use tauri::{Builder, WindowEvent};

Builder::default()
    .on_window_event(|window, event| {
        if let WindowEvent::CloseRequested { api, .. } = event {
            // Prevent default close behavior
            api.prevent_close();
            let _ = window.hide();
        }
    })
    .run(tauri::generate_context!())
    .expect("failed to run app");
```

## AppHandle

`AppHandle` is a cloneable handle to the running application. It implements `Send`, `Sync`, and `Clone`.

```rust
use tauri::{AppHandle, Manager};

fn background_worker(app: AppHandle) {
    std::thread::spawn(move || {
        // Access application state or windows across threads
        let path = app.path().app_data_dir().expect("valid app dir");
        println!("Working in directory: {:?}", path);
    });
}
```

Key features of `AppHandle`:
- Cheap to clone across threads or async tasks.
- Implements the `tauri::Manager` trait for state and window retrieval.
- Implements the `tauri::Emitter` trait for broadcasting events.

## Tokio Async Runtime

Tauri runs on top of the Tokio multi-threaded asynchronous runtime.

Use `tauri::async_runtime` to spawn cooperative background tasks:

```rust
use tauri::async_runtime::spawn;

tauri::Builder::default()
    .setup(|app| {
        let handle = app.handle().clone();
        spawn(async move {
            tokio::time::sleep(std::time::Duration::from_secs(5)).await;
            println!("Background task finished on Tokio runtime");
        });
        Ok(())
    })
    .run(tauri::generate_context!())
    .expect("error running app");
```

Command handlers marked with `async fn` run automatically on Tokio worker threads without blocking UI rendering.

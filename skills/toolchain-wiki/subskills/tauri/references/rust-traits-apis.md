## Why Explicit Trait Imports Matter

In Rust, calling a method on a struct requires the defining trait in lexical scope.

Tauri struct types like `App`, `AppHandle`, and `WebviewWindow` do not implement window or event methods as direct inherent methods. Instead, they implement extension traits.

If you omit the trait import, compilation fails with this error:

```plaintext
error[E0599]: no method named `get_webview_window` found for struct `App` in the current scope
   --> src/lib.rs:12:17
    |
 12 |     let win = app.get_webview_window("main");
    |                   ^^^^^^^^^^^^^^^^^^
    = help: items from traits can only be used if the trait is in scope
    = help: the following trait is implemented but not in scope; use it via a browse:
            `use tauri::Manager;`
```

Always bring the required traits into scope at the top of your file:

```rust
use tauri::{Emitter, Listener, Manager};
```

## Core Traits Reference

| Trait | Structs Implementing | Key Methods | Purpose |
| ----- | -------------------- | ----------- | ------- |
| `tauri::Manager` | `App`, `AppHandle`, `WebviewWindow` | `get_webview_window`, `manage`, `state`, `path` | State storage, window lookup, path resolution |
| `tauri::Emitter` | `App`, `AppHandle`, `WebviewWindow` | `emit`, `emit_to`, `emit_filter` | Sending asynchronous events from Rust to frontend |
| `tauri::Listener` | `App`, `AppHandle`, `WebviewWindow` | `listen`, `listen_any`, `unlisten` | Receiving events from frontend or other components |

## Manager Trait

The `tauri::Manager` trait provides access to application-wide resources and handles.

```rust
use tauri::{AppHandle, Manager};

pub fn check_environment(app: &AppHandle) {
    // Resolve application paths
    let config_dir = app.path().app_config_dir().expect("valid path");
    println!("Config directory: {:?}", config_dir);

    // Retrieve a window by label
    if let Some(window) = app.get_webview_window("main") {
        let _ = window.set_focus();
    }
}
```

Notice the rename in Tauri 2.0: `get_window` is now `get_webview_window`.

## Emitter and Listener Traits

Tauri provides bi-directional event communication between Rust and the frontend.

### Emitting Events from Rust

```rust
use serde::Serialize;
use tauri::{AppHandle, Emitter, EventTarget};

#[derive(Clone, Serialize)]
struct SystemStatus {
    cpu_percent: f32,
    memory_mb: u64,
}

pub fn broadcast_metrics(app: &AppHandle, status: SystemStatus) {
    // Broadcast to all windows and webviews
    app.emit("system-metrics", &status).unwrap();

    // Send only to the main window
    app.emit_to("main", "status-update", "online").unwrap();

    // Filter target windows with a predicate
    app.emit_filter("alert", "critical", |target| match target {
        EventTarget::WebviewWindow { label } => label == "dashboard",
        _ => false,
    }).unwrap();
}
```

### Listening to Events in Rust

```rust
use tauri::{AppHandle, Listener};

pub fn register_listeners(app: &AppHandle) {
    // Listen to an event from the frontend
    let handler_id = app.listen("client-ping", |event| {
        println!("Received payload: {}", event.payload());
    });

    // Listen to any event regardless of target filter
    app.listen_any("frontend-error", |event| {
        eprintln!("Frontend error: {}", event.payload());
    });

    // Unlisten when no longer needed
    app.unlisten(handler_id);
}
```

## Window Management

Create and configure windows dynamically using `WebviewWindowBuilder`.

```rust
use tauri::{AppHandle, WebviewUrl, WebviewWindowBuilder};

pub fn open_settings_window(app: &AppHandle) -> Result<(), tauri::Error> {
    // Check if the window already exists
    if let Some(existing) = app.get_webview_window("settings") {
        existing.set_focus()?;
        return Ok(());
    }

    // Create a new webview window
    WebviewWindowBuilder::new(app, "settings", WebviewUrl::App("settings.html".into()))
        .title("Application Settings")
        .inner_size(600.0, 400.0)
        .resizable(false)
        .center()
        .build()?;

    Ok(())
}
```

## Native Menus

Construct application menus and window menus using `MenuBuilder`.

```rust
use tauri::menu::{MenuBuilder, MenuItem, SubmenuBuilder};
use tauri::App;

pub fn setup_menu(app: &mut App) -> Result<(), tauri::Error> {
    let quit_item = MenuItem::with_id(app, "quit", "Quit App", true, None::<&str>)?;
    let file_submenu = SubmenuBuilder::new(app, "File")
        .item(&quit_item)
        .build()?;

    let menu = MenuBuilder::new(app)
        .item(&file_submenu)
        .build()?;

    app.set_menu(menu)?;

    app.on_menu_event(|app, event| {
        if event.id() == "quit" {
            app.exit(0);
        }
    });

    Ok(())
}
```

## System Tray

The `tray-icon` cargo feature is not a default feature. You must enable it in `src-tauri/Cargo.toml` to compile and import `tauri::tray::{TrayIconBuilder, TrayIconEvent}`:

```toml
[dependencies]
tauri = { version = "2", features = ["tray-icon"] }
```

Configure a system tray icon with a context menu:

```rust
use tauri::menu::{MenuBuilder, MenuItem};
use tauri::tray::{MouseButton, MouseButtonState, TrayIconBuilder, TrayIconEvent};
use tauri::{App, Manager};

pub fn setup_tray(app: &mut App) -> Result<(), tauri::Error> {
    let quit_i = MenuItem::with_id(app, "quit", "Quit", true, None::<&str>)?;
    let menu = MenuBuilder::new(app).item(&quit_i).build()?;

    TrayIconBuilder::new()
        .menu(&menu)
        .show_menu_on_left_click(false)
        .on_menu_event(|app, event| {
            if event.id() == "quit" {
                app.exit(0);
            }
        })
        .on_tray_icon_event(|tray, event| {
            if let TrayIconEvent::Click {
                button: MouseButton::Left,
                button_state: MouseButtonState::Up,
                ..
            } = event {
                let app = tray.app_handle();
                if let Some(window) = app.get_webview_window("main") {
                    let _ = window.show();
                    let _ = window.set_focus();
                }
            }
        })
        .build(app)?;

    Ok(())
}
```

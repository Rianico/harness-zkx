## Plugin Architecture

In Tauri 2.0, APIs are modular plugins rather than monolithic core features.

Each plugin provides:
- A Rust crate (`tauri-plugin-*`) handling native operating system APIs.
- An optional JavaScript or TypeScript client package (`@tauri-apps/plugin-*`).
- Pre-defined permission sets and scopes for the capability system.

## Plugin Installation Workflow

Adding any official plugin requires four coordinated steps.

### Step 1: Install Dependencies

```bash
# Add Rust crate to src-tauri/Cargo.toml
pnpm tauri add fs

# Alternatively add packages manually:
# cargo add tauri-plugin-fs --manifest-path src-tauri/Cargo.toml
# pnpm add @tauri-apps/plugin-fs
```

### Step 2: Register in Rust Builder

Register the plugin instance in `src-tauri/src/lib.rs`:

```rust
pub fn run() {
    tauri::Builder::default()
        .plugin(tauri_plugin_fs::init())
        .run(tauri::generate_context!())
        .expect("error running app");
}
```

### Step 3: Grant Capability Permissions

Add the plugin permission identifier to your capability file in `src-tauri/capabilities/default.json`:

```json
{
  "identifier": "default",
  "windows": ["main"],
  "permissions": [
    "core:default",
    "fs:default"
  ]
}
```

If you omit the capability permission, IPC calls from the frontend fail with permission denied errors.

### Step 4: Consume in Frontend

```typescript
import { readTextFile, BaseDirectory } from '@tauri-apps/plugin-fs';

const content = await readTextFile('settings.json', {
  baseDir: BaseDirectory.AppConfig,
});
console.log('Loaded settings:', content);
```

## Custom Plugin Development

Author custom plugins to encapsulate reusable backend logic across applications.

### Scaffold a New Plugin

```bash
npx @tauri-apps/cli plugin new my-custom-plugin
```

Plugin naming conventions:
- Rust crate name must follow `tauri-plugin-<name>`.
- Identifiers use lowercase ASCII letters, numbers, and single hyphens.
- Underscores and uppercase characters trigger build errors.

### Implement the Plugin in Rust

```rust
// tauri-plugin-custom/src/lib.rs
use tauri::{
    plugin::{Builder, TauriPlugin},
    Runtime,
};

#[tauri::command]
fn ping() -> &'static str {
    "pong"
}

pub fn init<R: Runtime>() -> TauriPlugin<R> {
    Builder::new("custom")
        .invoke_handler(tauri::generate_handler![ping])
        .setup(|app, _api| {
            println!("Custom plugin initialized for {}", app.package_info().name);
            Ok(())
        })
        .build()
}
```

### Plugin Lifecycle Events

Plugins intercept host application events through builder hooks:
- `setup`: Initializes managed state and background workers.
- `on_webview_ready`: Configures newly created webview windows.
- `on_event`: Monitors native OS event loop dispatches.
- `on_drop`: Cleans up allocated resources upon application termination.

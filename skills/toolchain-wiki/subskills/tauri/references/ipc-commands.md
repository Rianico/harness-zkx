## Command Definition

Annotate Rust functions with the `#[tauri::command]` attribute to expose them to the webview.

```rust
// src-tauri/src/commands.rs
use serde::{Deserialize, Serialize};

#[derive(Serialize, Deserialize)]
pub struct UserProfile {
    pub id: u64,
    pub name: String,
}

#[tauri::command]
pub fn fetch_user(user_id: u64) -> UserProfile {
    UserProfile {
        id: user_id,
        name: "Developer".to_string(),
    }
}
```

Register commands with the builder using the `tauri::generate_handler!` macro:

```rust
// src-tauri/src/lib.rs
mod commands;

pub fn run() {
    tauri::Builder::default()
        .invoke_handler(tauri::generate_handler![commands::fetch_user])
        .run(tauri::generate_context!())
        .expect("failed to run app");
}
```

Commands defined in separate modules must use `pub fn`. Command names must remain unique across the entire application.

## Frontend Invoke

Import `invoke` from `@tauri-apps/api/core` in JavaScript or TypeScript.

```typescript
import { invoke } from '@tauri-apps/api/core';

interface UserProfile {
  id: number;
  name: string;
}

// Arguments pass as a JSON object with camelCase keys by default
const user = await invoke<UserProfile>('fetch_user', {
  userId: 42,
});
console.log(user.name);
```

### Argument Naming Conventions

By default, Tauri translates Rust `snake_case` parameter names to JavaScript `camelCase`.

| Rust Signature | JavaScript Payload Key |
| -------------- | ---------------------- |
| `fn save(user_id: u64)` | `{ userId: 10 }` |
| `fn search(query_string: String)` | `{ queryString: "term" }` |

To keep snake_case on the frontend, add the `rename_all` attribute to the command macro:

```rust
#[tauri::command(rename_all = "snake_case")]
pub fn update_entry(item_id: u32, new_value: String) {}
```

Frontend call:

```typescript
await invoke('update_entry', { item_id: 1, new_value: 'data' });
```

## Binary Data and Buffers

Serializing large binary buffers to JSON strings degrades performance. Use `tauri::ipc::Response` to transmit raw byte vectors directly.

```rust
use tauri::ipc::Response;

#[tauri::command]
pub fn read_asset_bytes(path: String) -> Result<Response, String> {
    let bytes = std::fs::read(&path).map_err(|e| e.to_string())?;
    Ok(Response::new(bytes))
}
```

Frontend handling:

```typescript
import { invoke } from '@tauri-apps/api/core';

const buffer = await invoke<ArrayBuffer>('read_asset_bytes', {
  path: 'data.bin',
});
const bytes = new Uint8Array(buffer);
```

## Error Handling

Return `Result<T, E>` from command handlers to surface errors to the frontend.

```rust
#[tauri::command]
pub fn perform_calculation(input: i32) -> Result<i32, String> {
    if input < 0 {
        return Err("Input must be a non-negative integer".to_string());
    }
    Ok(input * 2)
}
```

When a command returns `Err(message)`, the frontend promise rejects:

```typescript
try {
  const result = await invoke<number>('perform_calculation', { input: -5 });
} catch (error) {
  console.error('Command rejected with error:', error);
}
```

### Typed Errors with `thiserror`

All error types returned to the frontend must implement `serde::Serialize`.

```rust
#[derive(Debug, thiserror::Error)]
pub enum AppError {
    #[error("File I/O error: {0}")]
    Io(#[from] std::io::Error),
    #[error("Parse error: {0}")]
    Parse(String),
}

impl serde::Serialize for AppError {
    fn serialize<S>(&self, serializer: S) -> Result<S::Ok, S::Error>
    where
        S: serde::Serializer,
    {
        serializer.serialize_str(self.to_string().as_str())
    }
}

#[tauri::command]
pub fn read_config(path: String) -> Result<String, AppError> {
    let content = std::fs::read_to_string(path)?;
    Ok(content)
}
```

## Managed State

Inject shared application state into commands using `tauri::State<'_, T>`.

### Synchronous State

Wrap shared state in `std::sync::Mutex` for thread-safe access:

```rust
use std::sync::Mutex;
use tauri::{Manager, State};

#[derive(Default)]
pub struct AppCounter {
    pub value: u64,
}

#[tauri::command]
pub fn increment_counter(state: State<'_, Mutex<AppCounter>>) -> Result<u64, String> {
    let mut counter = state.lock().map_err(|e| e.to_string())?;
    counter.value += 1;
    Ok(counter.value)
}

pub fn run() {
    tauri::Builder::default()
        .setup(|app| {
            app.manage(Mutex::new(AppCounter::default()));
            Ok(())
        })
        .invoke_handler(tauri::generate_handler![increment_counter])
        .run(tauri::generate_context!())
        .expect("error running app");
}
```

### Asynchronous State with Tokio

If a command locks a mutex across `.await` points, use `tokio::sync::Mutex`.

```rust
use tokio::sync::Mutex;
use tauri::State;

pub struct DatabaseConnection {
    pub connection_url: String,
}

#[tauri::command]
pub async fn query_database(
    state: State<'_, Mutex<DatabaseConnection>>,
) -> Result<String, String> {
    let db = state.lock().await;
    // Async command taking borrowed State must return Result
    Ok(format!("Connected to {}", db.connection_url))
}
```

Commands taking borrowed parameters like `State<'_, T>` in `async fn` must return a `Result` type.

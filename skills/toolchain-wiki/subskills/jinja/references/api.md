## Basics

`Environment` is the central object. It stores configuration, globals, filters and tests, and loads templates from the file system or other locations. Create one at application init and reuse it. `$SKILL_DIR/references/jinja-raw/003-api.md` lines 5–40.

`Template(...)` builds a shared anonymous environment behind the scenes when called directly. Multiple templates constructed with the same arguments may share that ephemeral environment. [`003-api.md#basics`](jinja-raw/003-api.md)

The canonical setup, using `PackageLoader` and `select_autoescape`:

```python
from jinja2 import Environment, PackageLoader, select_autoescape

env = Environment(
    loader=PackageLoader("yourapp"),
    autoescape=select_autoescape(),
)
template = env.get_template("mytemplate.html")
print(template.render(the="variables", go="here"))
```

`PackageLoader` looks in the `templates` folder inside the `yourapp` package (or next to `yourapp.py`). It only requires that `yourapp` is importable. [`003-api.md#basics`](jinja-raw/003-api.md)

Prefer a loader over `Template` / `Environment.from_string()`: it is easier and it enables template inheritance. [`003-api.md#basics`](jinja-raw/003-api.md)

> [!WARNING]
> An environment may only be modified while no template has been loaded. Later modifications lead to surprising effects and undefined behavior. Install dependencies via `pip install Jinja2`; MarkupSafe is required, Babel is optional. `$SKILL_DIR/references/jinja-raw/002-intro.md` lines 20–47.

## `Environment` constructor options

`class jinja2.Environment([options])` — signature and defaults below are taken verbatim from `$SKILL_DIR/references/jinja-raw/003-api.md` lines 63–236.

| Option                 | Default    | Effect                                                                       |
| ---------------------- | ---------- | ---------------------------------------------------------------------------- |
| `block_start_string`   | `'{%'`     | Marks the beginning of a block.                                              |
| `block_end_string`     | `'%}'`     | Marks the end of a block.                                                    |
| `variable_start_string`| `'{{'`     | Marks the beginning of a print statement.                                    |
| `variable_end_string`  | `'}}'`     | Marks the end of a print statement.                                          |
| `comment_start_string` | `'{#'`     | Marks the beginning of a comment.                                            |
| `comment_end_string`   | `'#}'`     | Marks the end of a comment.                                                  |
| `line_statement_prefix`| unset      | Prefix for line based statements. See Line Statements.                       |
| `line_comment_prefix`  | unset      | Prefix for line based comments (added in 2.2).                               |
| `trim_blocks`          | `False`    | Removes the first newline after a **block** tag (not variable tags).         |
| `lstrip_blocks`        | `False`    | Strips leading spaces/tabs from line start to a block.                       |
| `newline_sequence`     | `'\n'`     | Must be `'\r'`, `'\n'` or `'\r\n'`.                                          |
| `keep_trailing_newline`| `False`    | When `False`, one trailing newline is stripped (added in 2.7).               |
| `extensions`           | —          | Jinja extensions, as import-path strings or extension classes.               |
| `optimized`            | `True`     | Enables the optimizer.                                                       |
| `undefined`            | `Undefined`| Undefined type used for failed lookups; a `Undefined` subclass.              |
| `finalize`             | `None`     | Callable that post-processes every variable expression before output.        |
| `autoescape`           | `False`    | `True`, or a callable receiving the template name and returning a bool.      |
| `loader`               | `None`     | The template loader.                                                         |
| `cache_size`           | `400`      | Template cache size; `0` recompiles always, `-1` never cleans (raised from 50 in 2.8). |
| `auto_reload`          | `True`     | Reload a template when its source changed. Disable for higher performance.   |
| `bytecode_cache`       | `None`     | A bytecode cache object so templates need not be re-parsed.                  |
| `enable_async`         | `False`    | Enables async template execution (async functions and generators).           |

Typed signature (from the same range): `autoescape` is `bool | Callable[[str | None], bool]`; `undefined` is `Type[Undefined]`; `newline_sequence` is `Literal['\n', '\r\n', '\r']`.

### Environment methods

`overlay([options])` creates a shared-data environment that overrides selected attributes; cache is not shared, extensions cannot be removed. Creating overlays should happen after the initial environment is fully set up — some attributes are copied, not linked. `enable_async` is applied correctly since 3.1.5; `newline_sequence`, `keep_trailing_newline` and `enable_async` were added to it in 3.1.2. [`003-api.md#Environment.overlay`](jinja-raw/003-api.md)

`undefined([hint, obj, name, exc])` builds an `Undefined` for a name, for use in filters or functions. Pass everything except `hint` as keywords. `hint` becomes the error message; `exc` (default `UndefinedError`) is raised on disallowed operations. If `hint` is given, `name` may be omitted. `$SKILL_DIR/references/jinja-raw/003-api.md` lines 250–285.

```python
return environment.undefined(name="some_name")
return environment.undefined(obj=obj, name="attr")
return environment.undefined("no first item, sequence was empty")
```

`add_extension(extension)` adds an extension after creation (added in 2.5). `extend(**attributes)` adds attributes if they do not exist; extensions use it to register callbacks without breaking inheritance.

`compile_expression(source, undefined_to_none=True)` returns a callable taking the expression's variables as keyword arguments. With `undefined_to_none=False` an undefined result is returned as `Undefined` rather than `None` (added in 2.1).

```python
env = Environment()
expr = env.compile_expression("foo == 42")
expr(foo=23)   # False
expr(foo=42)   # True
env.compile_expression("var")() is None  # True
```

`compile_templates(target, extensions=None, filter_func=None, zip='deflated', log_function=None, ignore_errors=True)` compiles every template the loader can find into `target`. `zip=None` writes a directory instead of a zipfile; `zip='stored'` switches the algorithm. `extensions` and `filter_func` are passed to `list_templates()`. Compilation errors are ignored unless `ignore_errors=False` (added in 2.4).

`list_templates(extensions=None, filter_func=None)` returns template names; requires loader support, else `TypeError`. Filter by a list of file extensions or by a `filter_func(name) -> bool`.

`join_path(template, parent)` joins a template with its parent; the default returns `template` unchanged because lookups are loader-root relative.

| Method                                                          | Behaviour                                                                     |
| --------------------------------------------------------------- | ----------------------------------------------------------------------------- |
| `get_template(name, parent=None, globals=None)`                 | Load by name; raises `TemplateNotFound`. `/` is the separator even on Windows. |
| `select_template(names, parent=None, globals=None)`             | Try names in order; raises `TemplatesNotFound`.                                |
| `get_or_select_template(template_name_or_list, ...)`            | Dispatch to the two above based on argument shape.                             |
| `from_string(source, globals=None, template_class=None)`        | Compile a source string without a loader.                                      |

`globals` extends `Environment.globals` for all renders of that template. Since 3.0, loading a cached template updates its globals instead of ignoring the new values. Since 2.4 a `Template` passed as `name`/in `names` is returned unchanged. `select_template` raises `UndefinedError` when `names` is `Undefined` (2.11).

## `Template`

`class jinja2.Template(source, ...)` takes most `Environment` arguments; defaults include `extensions=()`, `optimized=True`, `undefined=Undefined`, `finalize=None`, `autoescape=False`, `enable_async=False`. Templates are immutable; use the `Environment` methods instead of this constructor. `$SKILL_DIR/references/jinja-raw/003-api.md` lines 505–580.

| Member                                             | Notes                                                                      |
| -------------------------------------------------- | -------------------------------------------------------------------------- |
| `render([context])`                                | Accepts a dict/subclass or kwargs; returns one string. Empty context if none. |
| `generate([context])`                              | Generator yielding pieces as strings; same arguments as `render()`.        |
| `stream([context])`                                | Same as `generate()` but returns a `TemplateStream`.                       |
| `async render_async([context])`                    | Coroutine returning the full string; requires async enabled.               |
| `async generate_async([context])`                  | Async iterator version of `generate()`.                                    |
| `make_module(vars=None, shared=False, locals=None)`| Evaluate the template as a module on every call (no caching).              |
| `module`                                           | Property: template as `TemplateModule`; absent when async mode is enabled. |
| `globals`                                          | Per-template globals; defaults to `Environment.globals`. Do not modify.    |
| `name` / `filename`                                | Load name; file name if loaded from the file system. `None` for strings.   |

`render(knights='that say nih')` and `render({'knights': 'that say nih'})` are equivalent. `module` exposes exported template variables from Python:

```python
t = Template('{% macro foo() %}42{% endmacro %}23')
str(t.module)        # '23'
t.module.foo() == '42'  # True
```

`TemplateStream` buffers output to reduce iteration count; unbuffered by default. `enable_buffering(size=5)` combines items, `disable_buffering()` reverts. `dump(fp, encoding=None, errors='strict')` writes the whole stream to a file or file-like object:

```python
Template('Hello {{ name }}!').stream(name='foo').dump('hello.html')
```

## Autoescaping

Autoescaping is built in since Jinja 2.9 (the extension was removed) but is **not enabled by default**; configure it explicitly, as it may become the default. Inside templates the `autoescape` block overrides it per region. `$SKILL_DIR/references/jinja-raw/003-api.md` lines 701–760.

`jinja2.select_autoescape(enabled_extensions=('html', 'htm', 'xml'), disabled_extensions=(), default_for_string=True, default=False)` sets the initial value from the template filename. It is case insensitive for security. A filename matching nothing gets `default`; a string template gets `default_for_string`. Added in 2.9.

```python
from jinja2 import Environment, select_autoescape

# Enable for .html/.xml, and for templates created from strings
env = Environment(autoescape=select_autoescape(
    enabled_extensions=('html', 'xml'),
    default_for_string=True,
))

# On everywhere except .txt templates
env = Environment(autoescape=select_autoescape(
    disabled_extensions=('txt',),
    default_for_string=True,
    default=True,
))
```

A custom guessing callable must accept `None` as a valid template name; `None` is passed for string-generated templates. In filters, check autoescape on the **evaluation context**, not the environment — see [Evaluation Context](#evaluation-context).

## Identifiers

Jinja uses Python naming rules. Filters and tests live in separate namespaces and allow dotted names for grouping, e.g. `to.str`. Their identifier regex is `[a-zA-Z_][a-zA-Z0-9_]*(\.[a-zA-Z_][a-zA-Z0-9_]*)*`. `$SKILL_DIR/references/jinja-raw/003-api.md` lines 762–770.

## Undefined types

Passed via `Environment(undefined=...)`, or a custom `Undefined` subclass. A failed name lookup or attribute access produces one of these objects.

| Class                     | Print         | Iterate / bool / compare | Other ops                     |
| ------------------------- | ------------- | ------------------------ | ----------------------------- |
| `Undefined` (default)     | `''`          | allowed                  | raise `UndefinedError`        |
| `ChainableUndefined` (2.11)| `''`         | allowed                  | `__getattr__`/`__getitem__` chain and return itself |
| `DebugUndefined`          | `'{{ foo }}'` | allowed                  | raise `UndefinedError`        |
| `StrictUndefined`         | raises        | raises                   | raises; only `defined` test works |

All four share the parameters `hint`, `obj`, `name`, `exc`. `StrictUndefined` is closest to regular Python behavior: it disallows all operations except testing whether it is an undefined object. `$SKILL_DIR/references/jinja-raw/003-api.md` lines 772–880.

`jinja2.make_logging_undefined(logger=None, base=Undefined)` is a factory returning an undefined class that logs iterations and printing; a default logger is created when `logger` is omitted (added in 2.8).

```python
logger = logging.getLogger(__name__)
LoggingUndefined = make_logging_undefined(logger=logger, base=Undefined)
```

Implementation contract: `Undefined` overrides the special `__underscore__` methods, so a subclass can change what operations succeed. To forbid a method, override it and raise `_undefined_exception`, or call the helper `_fail_with_undefined_error()`.

```python
class NullUndefined(Undefined):
    def __int__(self):
        return 0

    def __float__(self):
        return 0.0


class NonIterableUndefined(Undefined):
    def __iter__(self):
        self._fail_with_undefined_error()
```

Introspection attributes: `_undefined_hint`, `_undefined_obj`, `_undefined_name`, `_undefined_exception`.

## The Context

`class jinja2.runtime.Context` holds a template's variables and exported names. It is created automatically during evaluation and must not be created by hand. It is immutable: `parent` must not be modified, and `vars` may only be modified by generated template code. [`003-api.md#the-context`](jinja-raw/003-api.md)

| Member            | Meaning                                                                        |
| ----------------- | ------------------------------------------------------------------------------ |
| `parent`          | Read-only globals the template looks up; must not be altered.                  |
| `vars`            | Template locals: env/context functions from `parent`, local mods, exported vars. |
| `environment`     | The environment that loaded the template.                                      |
| `exported_vars`   | Set of names the template exports; values live in `vars`.                      |
| `name`            | Load name of the owning template.                                              |
| `blocks`          | Mapping of block name → list of registered blocks; last item is the active one. |
| `eval_ctx`        | The current `EvalContext`.                                                     |

Read-only dict operations are supported (`get`, `keys`, `values`, `items`, `__getitem__`, `__contains__`). Methods:

- `call(callable, *args, **kwargs)` injects the context or environment when the callable is decorated with `pass_context()` / `pass_environment()`.
- `resolve(key)` returns an `Undefined` instead of raising `KeyError`.
- `resolve_or_missing(key)` returns a `missing` sentinel; override **this** to add custom lookup behavior — `resolve()`, `get()` and `__getitem__()` call it.
- `get_exported()` copies exported variables; `get_all()` returns the whole context as a dict (possibly not a copy).

The context is a data source, not storage: variables the template defines are stored locally. A function should return a value assigned inside the template rather than mutate the context.

```jinja
{% set comments = get_latest_comments() %}
```

## Loaders

Loaders fetch template sources. The environment caches compiled modules like `sys.modules`, but with a size limit (`cache_size`) and optional auto-reload. All subclasses override `get_source`. `$SKILL_DIR/references/jinja-raw/003-api.md` lines 1100–1250.

| Loader                                   | Signature (defaults)                          | Use for                                        |
| ---------------------------------------- | --------------------------------------------- | ---------------------------------------------- |
| `FileSystemLoader`                       | `(searchpath, encoding='utf-8', followlinks=False)` | Directories; a list is searched in order, first match wins. |
| `PackageLoader`                          | `(package_name, package_path='templates', encoding='utf-8')` | Templates inside an importable package (pip dirs, zip/egg; limited PEP 420). |
| `DictLoader`                             | `(mapping)`                                   | Tests; auto reloading disabled by default.     |
| `FunctionLoader`                         | `(load_func)`                                 | Callable returns source, a `(source, filename, uptodatefunc)` tuple, or `None`. |
| `PrefixLoader`                           | `(mapping, delimiter='/')`                    | Namespaced loaders, e.g. `'app1/index.html'`.  |
| `ChoiceLoader`                           | `(loaders)`                                   | Fallback chains; user templates overriding builtins. |
| `ModuleLoader`                           | `(path)`                                      | Precompiled templates from `compile_templates()`. |

`BaseLoader.get_source(environment, template)` must return `(source, filename, uptodate)` or raise `TemplateNotFound`. `source` is a string; `filename` is the file system path or `None`; `uptodate` takes no arguments and returns `False` when the template must be reloaded. Do **not** override `BaseLoader.load()` — collection loaders call `get_source` directly.

```python
from jinja2 import BaseLoader, TemplateNotFound
from os.path import join, exists, getmtime


class MyLoader(BaseLoader):
    def __init__(self, path):
        self.path = path

    def get_source(self, environment, template):
        path = join(self.path, template)
        if not exists(path):
            raise TemplateNotFound(template)
        mtime = getmtime(path)
        with open(path) as f:
            source = f.read()
        return source, path, lambda: mtime == getmtime(path)
```

## Bytecode Cache

Available since Jinja 2.1. A bytecode cache stores generated bytecode so templates are not parsed on first use — useful when an application compiles many templates at startup. Pass the instance as `Environment(bytecode_cache=...)`. `$SKILL_DIR/references/jinja-raw/003-api.md` lines 1241–1380.

Subclass `jinja2.BytecodeCache` and override `load_bytecode(bucket)` (do nothing if absent) and `dump_bytecode(bucket)` (raise on failure, never fail silently). Also implement `clear()`; Jinja does not call it.

| Cache                                     | Signature (defaults)                                                                 |
| ----------------------------------------- | ----------------------------------------------------------------------------------- |
| `FileSystemBytecodeCache`                 | `(directory=None, pattern='__jinja2_%s.cache')`; `%s` is the cache key. Default dir: temp dir (per-user on UNIX). Supports `clear()`. |
| `MemcachedBytecodeCache`                  | `(client, prefix='jinja2/bytecode/', timeout=None, ignore_memcache_errors=True)`; client needs `set(key, value[, timeout])` and `get(key)`; `clear()` is a no-op. |

`jinja2.bccache.Bucket(environment, key, checksum)` holds one template's bytecode; the cache assigns the checksum, so caches need no invalidation logic. Members: `environment`, `key`, `code` (bytecode or `None`); methods `reset()`, `load_bytecode(f)`, `write_bytecode(f)`, `bytecode_from_string(string)`, `bytecode_to_string()`.

## Async support

Added in Jinja 2.9 and off by default. Enable with `Environment(enable_async=True)`; templates look identical to the designer. `$SKILL_DIR/references/jinja-raw/003-api.md` line 1355 onwards.

Implications of enabling async:

- The compiled code uses `await` for calls and attributes and `async for` loops.
- A wrapper around every call and access supports mixing sync and async, at some overhead versus pure async code.
- Sync methods become wrappers: `render` invokes `async_render`, `|map` supports async iterables.
- Awaitable objects returned by template functions are awaited implicitly.

```python
env = Environment(enable_async=True)
template = env.from_string("{{ knights }}")
await template.render_async(knights="that say nih; asynchronously")
```

Configured through `env.policies`, added in Jinja 2.9; usually security related.

## Utilities

Helper decorators and functions for custom filters, tests and functions. `$SKILL_DIR/references/jinja-raw/003-api.md` lines 1440–1500.

- `pass_context(f)` — passes the `Context` as first argument. Added in 3.0.0, replacing `contextfunction` / `contextfilter`.
- `pass_eval_context(f)` — passes the `EvalContext` as first argument, replacing `evalcontextfunction` / `evalcontextfilter`.
- `pass_environment(f)` — passes the `Environment` as first argument, replacing `environmentfunction` / `environmentfilter`.
- `clear_caches()` — clears Jinja's internal environment and lexer caches; use when measuring memory.
- `is_undefined(obj)` — instance check against `Undefined` for custom filters and tests.

```python
from jinja2 import is_undefined


def default(var, default=""):
    if is_undefined(var):
        return default
    return var
```

## Evaluation Context

`class jinja2.nodes.EvalContext(environment, template_name=None)` toggles compiled features at runtime. It currently only carries autoescaping, but extensions may use it. `$SKILL_DIR/references/jinja-raw/003-api.md` lines 1770–1840.

Attributes: `autoescape` (`True`/`False` for the current template) and `volatile` (`True` if the compiler could not evaluate some expressions at compile time; always `False` at runtime).

Check autoescaping on the eval context, not the environment — the eval context holds the computed per-template value.

```python
@pass_eval_context
def filter(eval_ctx, value):
    result = do_something(value)
    if eval_ctx.autoescape:
        result = Markup(result)
    return result
```

Use `pass_context` when other context behavior is needed (`context.eval_ctx.autoescape`). The eval context must not be modified at runtime; changes only via `nodes.EvalContextModifier` and `nodes.ScopedEvalContextModifier` from an extension.

## Global Namespace

`Environment.globals` is for data common to all templates of an environment; `Template.globals` is for data common to all renders of one template, defaulting to `Environment.globals` unless overridden in `get_template()`. Render-specific data belongs in `render()`. [`003-api.md#the-global-namespace`](jinja-raw/003-api.md)

Only one set of globals is used per rendering: if B extends A and both have template globals, `b.render()` uses only B's. Do not change environment globals after loading templates, nor template globals at any time.

## Low Level API

Not recommended unless you know exactly what you are doing; the surface is fragile across versions. `$SKILL_DIR/references/jinja-raw/003-api.md` lines 1845–1935.

- `Environment.lex(source, name=None, filename=None)` — generator of `(lineno, token_type, value)` tuples. No preprocessing; filter through `preprocess()` if extensions must apply.
- `Environment.parse(source, name=None, filename=None)` — abstract syntax tree used by the compiler; useful for debugging and extension development.
- `Environment.preprocess(source, name=None, filename=None)` — applies extension preprocessing; called automatically by parsing and compiling, not by `lex()`.
- `Template.new_context(vars=None, shared=False, locals=None)` — build a `Context`; with `shared=True` globals are not added.
- `Template.root_render_func(context)` — compiler-generated generator yielding strings; call only from `render()` / `generate()` / `stream()`. Exceptions pass through unrevised.
- `Template.blocks` — dict of block render functions with the same limitations.
- `Template.is_up_to_date` — `False` when a newer template version exists.

## Meta API

Added in Jinja 2.2. All functions operate on an AST from `Environment.parse()`. `$SKILL_DIR/references/jinja-raw/003-api.md` lines 1940–1974.

`jinja2.meta.find_undeclared_variables(ast)` returns the set of variables looked up from the context at runtime. All variables are returned because the execution path is unknown at compile time. Internally it uses the code generator, so it can raise `TemplateAssertionError`.

```python
from jinja2 import Environment, meta

env = Environment()
ast = env.parse("{% set foo = 42 %}{{ bar + foo }}")
meta.find_undeclared_variables(ast) == {"bar"}  # True
```

`jinja2.meta.find_referenced_templates(ast)` iterates over hardcoded template names from extends, includes and imports; dynamic references yield `None`. It supports dependency tracking, e.g. rebuilding pages after a layout change.

```python
ast = env.parse('{% extends "layout.html" %}{% include helper %}')
list(meta.find_referenced_templates(ast))  # ['layout.html', None]
```

**Done when:** you can build an `Environment` with the options table, load a template through a documented loader, and predict what each `undefined` class does on print, iterate and arithmetic.

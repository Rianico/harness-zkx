## 3.1.x

### 3.1.0 — deprecated surface removed

[013-changes.md#version-310](jinja-raw/013-changes.md)

- Python 3.6 support dropped.
- Deprecated code removed: the decorator aliases below, and the `Context.resolve` legacy resolve mode. Subclasses must override `resolve_or_missing` instead of `resolve`. `$SKILL_DIR/references/jinja-raw/013-changes.md`.
- `Markup` and `escape` must be imported from MarkupSafe, not from `jinja2`.
- `WithExtension` and `AutoEscapeExtension` are built-in now; drop them from `Environment(extensions=...)`.
- `unicode_urlencode` renamed to `url_quote`.
- Compiled templates from very old Jinja versions may need to be recompiled.
- `groupby` is case-insensitive by default, matching other comparison filters; the new `case_sensitive` parameter restores the old behaviour.
- `items` filter added; subscriptions (`[0]`) work after filters, tests and calls in async mode.
- Valid identifier characters updated from Python 3.6 to 3.7 rules — identifiers legal in 3.6 templates may now fail.
- `{% trans %}` accepts a context string as first token, enabling `pgettext` and `npgettext`.
- Windows drive-relative path segments in template names are refused by `FileSystemLoader` and `PackageLoader`.
- Macros gain support for native types.

### 3.1.2 – 3.1.6 — hardening and configuration

[013-changes.md#version-313](jinja-raw/013-changes.md)

- 3.1.2: `Environment.overlay` accepts parameters matching `Environment.__init__`. #1645
- 3.1.3: `xmlattr` rejects keys containing spaces. GHSA-h5c8-rqwp-cp95
- 3.1.4: `xmlattr` also rejects keys containing `/`, `>`, or `=`; spaces were already rejected. GHSA-h75v-3vvj-5mfj
- 3.1.5: the sandboxed environment handles indirect calls to `str.format`, such as a stored reference passed to a filter that calls its argument. `clear` and `pop` are refused on known mutable sequence types.
- 3.1.5: template names are escaped before being formatted into error messages; `FileSystemLoader` errors list the searched paths.
- 3.1.5: calling sync `render` on an async template uses `asyncio.run`, replacing 3.0.1's `asyncio.new_event_loop`. `Environment.overlay(enable_async)` is applied correctly.
- 3.1.6: `|attr` no longer bypasses the environment's attribute lookup, so the sandbox applies its checks. GHSA-cpwx-vrp4-4pq7

> [!WARNING]
> 3.1.3–3.1.6 are all sandbox or injection fixes. Any template rendering untrusted data must pin `jinja2 >= 3.1.6`. Never pass raw user input as `xmlattr` keys; the docs state validation is still the caller's job. [013-changes.md#version-314](jinja-raw/013-changes.md)

## API renames

Old names below were removed in 3.1.0; the new column is the only supported spelling. [013-changes.md#version-310](jinja-raw/013-changes.md)

| Old                                                                       | New                                      | Removed in   |
| ------------------------------------------------------------------------- | ---------------------------------------- | ------------ |
| `contextfilter`, `contextfunction`                                        | `pass_context`                           | 3.1.0        |
| `evalcontextfilter`, `evalcontextfunction`                                | `pass_eval_context`                      | 3.1.0        |
| `environmentfilter`, `environmentfunction`                                | `pass_environment`                       | 3.1.0        |
| `unicode_urlencode`                                                       | `url_quote`                              | 3.1.0        |
| `jinja2.Markup`                                                           | `markupsafe.Markup`                      | 3.1.0        |
| `jinja2.escape`                                                           | `markupsafe.escape`                      | 3.1.0        |
| `Context.resolve` (override point)                                        | `Context.resolve_or_missing`             | 3.1.0        |
| `jinja2.ext.WithExtension`, `jinja2.ext.AutoEscapeExtension`              | built-in `{% with %}` / `{% autoescape %}` | 3.1.0        |
| `jinja2.ext.with_`, `jinja2.ext.autoescape` in `extensions=`               | drop the entry                           | 3.0.1 warns  |

Registering the unneeded `autoescape` or `with_` extension produces a deprecation warning; 3.0.1 makes that warning show more relevant context [013-changes.md#version-301](jinja-raw/013-changes.md).

## 3.0.x

[013-changes.md#version-300](jinja-raw/013-changes.md)

- 3.0.0: Python 2.7 and 3.5 support dropped. MarkupSafe dependency bumped to `>=1.1`, optional Babel to `>=2.1`.
- 3.0.0: code marked deprecated was removed, and type hints were added across the package.
- 3.0.0: `PackageLoader` loads templates through the PEP 451 API, not `pkg_resources`.
- 3.0.0: `+%}` after a block tag overrides `trim_blocks` for that tag.
- 3.0.0: blocks can be marked `required`; they must be overridden somewhere in the chain, not necessarily by the direct child.
- 3.0.0: imported macros regain access to the current template's globals (`#688`).
- 3.0.1: MarkupSafe dependency becomes `>=2.0`; `jinja2.Markup` was already deprecated — use `markupsafe.Markup`.
- 3.0.1: calling sync `render` for an async template uses `asyncio.new_event_loop`, replacing the Python 3.10-deprecated path.
- 3.0.2 and 3.0.3 carry only bugfixes; no migration action.

## 2.11

### 2.11.0

[013-changes.md#version-2110](jinja-raw/013-changes.md)

- Python 2.6, 3.3 and 3.4 support dropped. This is the last release supporting Python 2.7 and 3.5.
- `ChainableUndefined` added: it supports `getitem` and `getattr` on an undefined object.
- `{%+` is allowed even when `lstrip_blocks` is disabled, with no effect.
- The `map` filter gains a `default` parameter. See [filters](filters.md).
- Environment globals are excluded from `meta.find_undeclared_variables()`.
- New tests: `boolean`, `false`, `true`, `integer`, `float`. See [tests](tests.md).
- Float literals accept scientific notation (`2.56e-3`) and int/float literals accept `_` separators (`12_345`).
- The `trim` filter takes an optional string of characters to strip.
- New `jinja2.ext.debug` extension adds a `{% debug %}` tag dumping the context, filters and tests.
- `finalize` now applies only to expression output, never to static template data — a default change visible in whitespace-sensitive output.
- `{{ 'foo' if bar }}` with no `else` always returns `Undefined`, regardless of the environment's `undefined` class, so `StrictUndefined` no longer raises there.
- `PackageLoader` no longer depends on setuptools or `pkg_resources`; `FileSystemLoader` and `ModuleLoader` accept `os.PathLike`.
- Constructing a `NativeTemplate` directly creates a `NativeEnvironment` instead of a default `Environment`.
- `wordwrap` treats existing newlines as separate paragraphs, and gains `break_on_hyphens`.
- A `DerivedContextReference` node lets extensions reach the current context and locals such as `loop`.
- Passing an `Undefined` value to `get_template` (via `extends`, `import`, `include`) raises `UndefinedError` consistently.
- `TemplateSyntaxError` is picklable, and its `source` is non-empty when raised from an included template.

## 2.10

[013-changes.md#version-210](jinja-raw/013-changes.md)

- New `OverlayScope` extension node creates an unoptimized scope resolving all variables from a derived context.
- `in` test added; comparison tests `eq`, `ne`, `lt`, `le`, `gt`, `ge` added.
- Loop contexts gain `previtem` and `nextitem`; both are undefined at the ends of the loop.
- Loop contexts gain `changed(*values)`, which reports whether a value differs since the previous call.
- New `namespace` function creates an object whose attributes are assignable with `set`, carrying data across scopes.
- `{% trans %}` gains a `trimmed` modifier stripping linebreaks and surrounding whitespace, plus a policy to enable it globally.
- `indent` no longer indents blank lines by default.
- `random` is no longer constant folded; it produces a new choice on each render.
- Filters added: `unique`, `min`, `max`; `dictsort` gains a `reverse` argument.
- `NativeEnvironment` renders to native Python types instead of strings. See [api](api.md).
- The block form of `set` accepts filters, and block sets are marked `safe` by default.
- `tojson` output is marked safe, matching the documented behaviour.
- An `import` statement can no longer end with a trailing comma.
- 2.10.1: `SandboxedEnvironment` secures `str.format_map`, as it already did `str.format`, preventing code execution through untrusted format strings.

## 2.9

[013-changes.md#version-29](jinja-raw/013-changes.md)

- Codename Derivation. Math operator precedence was corrected, so expressions that previously relied on the wrong precedence evaluate differently.
- The scoping system was rewritten: there is no longer any magic difference between `include` and `import` constructs. Context propagates identically; only the `with context` / `without context` defaults differ.
- Tests no longer accept an arbitrary expression as first argument, only a restricted one. `foo is divisibleby 2 or foo is divisibleby 3` now parses as expected.
- Macro autoescaping is decided by the runtime autoescaping information at call time, not at macro define time.
- `with` and `autoescape` are now built-in tags; `select_autoescape` was added to configure autoescaping.
- `urlize` sets `rel noopener` by default.
- Block sets are marked `safe` by default; `tojson` was ported from Flask and wired into the new policy framework.
- Subtraction now matches the other operators when applied to undefined values.
- The environment cache key definition changed, fixing a 2.8 performance regression.
- Added `generator_stop` support, Python 3.6 async iterators through the new async mode, and filter-default policies.
- On Python 2 only, asciification of ASCII strings is disabled with the `compiler.ascii_str` policy.
- Toplevel `set` statements work in `extends` situations.

## 2.x → 3.1 upgrade order

The raw changes document states removals and version floors, but documents no migration tool or compatibility shim.

1. Raise the interpreter floor to Python 3.7+: 3.0.0 dropped 2.7 and 3.5, 3.1.0 dropped 3.6.
2. Bump dependencies to MarkupSafe `>=2.0` (3.0.1) and optional Babel `>=2.1` (3.0.0).
3. Rewrite decorators and imports against the [renames table](#api-renames); switch `Context` subclasses to `resolve_or_missing`.
4. Drop `autoescape` / `with_` from `Environment(extensions=...)`; both tags are built-in.
5. Re-check autoescape-sensitive templates for the 2.9 macro-time → call-time change and the 3.1 `xmlattr` key restrictions.
6. Recompile any bytecode cache built by a very old Jinja version.

Audit a template tree for the constructs above before an upgrade:

```bash
rg -n 'contextfilter|evalcontextfilter|environmentfilter|unicode_urlencode|jinja2\.(Markup|escape)|xmlattr\(|\|[a-z]*urlencode' templates/
```

> [!TIP]
> Version-dependent symptoms usually trace to one of three changes: the 2.9 scoping rewrite, the 2.11 `finalize`/undefined-default changes, or the 3.1 decorator removals. Check the release map first, then the section for that release.

**Done when:** you can name the release that removed each API your project still imports, and the sandbox fix floor you must pin to.

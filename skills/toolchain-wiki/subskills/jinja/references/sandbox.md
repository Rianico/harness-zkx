## The security model in one screen

The sandbox lets a template render untrusted input while intercepting and prohibiting access to attributes, method calls, operators, mutating data structures and string formatting. [004-sandbox.md#sandbox](jinja-raw/004-sandbox.md)

It works by telling the compiler to emit sandboxed code. `SandboxedEnvironment` behaves like the regular environment otherwise. Subclasses override the methods that declare which attributes and functions are safe. [004-sandbox.md#api](jinja-raw/004-sandbox.md)

`SecurityError` is raised when a template touches insecure code. Other exceptions may still escape during rendering, so the caller must catch everything, not just `SecurityError`. [004-sandbox.md#api](jinja-raw/004-sandbox.md)

### What the sandbox does NOT protect against

These four limits are stated verbatim in the raw Security Considerations section. [004-sandbox.md#security-considerations](jinja-raw/004-sandbox.md)

| Limit | What you must do |
| --- | --- |
| Templates still raise errors when compiled or rendered | Catch errors instead of crashing |
| A small template can render to a very large amount of output | Run with limits on CPU and memory |
| Jinja only renders text; it does not understand JavaScript | Postprocess output depending on where it is used |
| Data you pass may carry side effects | Pass only relevant data; avoid globals and side-effecting methods |

> [!NOTE]
> Hardening add-ons named in the same section: override `is_safe_attribute()` to restrict attributes further, decorate methods with `unsafe()` to block calls from templates, and use `ImmutableSandboxedEnvironment` to prevent modifying lists and dictionaries. [004-sandbox.md#security-considerations](jinja-raw/004-sandbox.md)

### Documented use case

The raw docs describe an internal reporting system: you document which data is available, the user writes a template against it, and your code generates the report data and passes it to the user's sandboxed template. [004-sandbox.md#sandbox](jinja-raw/004-sandbox.md)

### Behaviour example

```pycon
>>> from jinja2.sandbox import SandboxedEnvironment
>>> env = SandboxedEnvironment()
>>> func = lambda: "Hello, Sandbox!"
>>> env.from_string("{{ func() }}").render(func=func)
'Hello, Sandbox!'
>>> env.from_string("{{ func.__code__.co_code }}").render(func=func)
Traceback (most recent call last):
    ...
SecurityError: access to attribute '__code__' of 'function' object is unsafe.
```

## `SandboxedEnvironment` API

`class jinja2.sandbox.SandboxedEnvironment([options])` — the sandboxed environment; takes `*args` / `**kwargs` passed through as options. [004-sandbox.md#api](jinja-raw/004-sandbox.md)

### Policy methods

| Member | Behaviour (defaults from raw) |
| --- | --- |
| `is_safe_attribute(obj, attr, value)` → `bool` | All attributes starting with an underscore are private, plus special attributes reported by `is_internal_attribute()` |
| `is_safe_callable(obj)` → `bool` | Callables are safe unless decorated with `unsafe()`; also honours the Django convention `func.alters_data = True` |
| `call_binop(context, operator, left, right)` → `Any` | Runs instead of the builtin operator for intercepted binary operators (added in 2.6) |
| `call_unop(context, operator, arg)` → `Any` | Runs instead of the builtin operator for intercepted unary operators (added in 2.6) |

### Operator tables

| Member | Default | Meaning |
| --- | --- | --- |
| `default_binop_table` | `{'%': mod, '*': mul, '**': pow, '+': add, '-': sub, '/': truediv, '//': floordiv}` | Class-level default callback table for binary operators |
| `binop_table` | copy of the above | Per-instance copy, available on each sandboxed environment |
| `default_unop_table` | `{'+': pos, '-': neg}` | Class-level default callback table for unary operators |
| `unop_table` | copy of the above | Per-instance copy, available on each sandboxed environment |
| `intercepted_binops` | `frozenset()` | Binary operators delegated to `call_binop()` |
| `intercepted_unops` | `frozenset()` | Unary operators delegated to `call_unop()` |

Interceptable binary operators: `//`, `%`, `+`, `*`, `-`, `/`, `**`. Interceptable unary operators: `+`, `-`. [004-sandbox.md#api](jinja-raw/004-sandbox.md)

> [!TIP]
> Intercepted calls are always slower than the native operator call. Intercept only the operators you actually care about. [004-sandbox.md#api](jinja-raw/004-sandbox.md)

### Helper functions

| Helper | Contract |
| --- | --- |
| `jinja2.sandbox.unsafe(f)` | Marks a function or method as unsafe, so `is_safe_callable()` rejects it |
| `jinja2.sandbox.is_internal_attribute(obj, attr)` | Tests for an internal Python attribute; `True` for `str.mro`, `False` for `str.upper` |
| `jinja2.sandbox.modifies_known_mutable(obj, attr)` | `True` if calling `attr` would mutate a builtin mutable (list, dict, set, deque) or its ABC; `False` for unsupported objects |

```pycon
>>> from jinja2.sandbox import is_internal_attribute
>>> is_internal_attribute(str, "mro")
True
>>> is_internal_attribute(str, "upper")
False
```

```pycon
>>> from jinja2.sandbox import modifies_known_mutable
>>> modifies_known_mutable({}, "clear")
True
>>> modifies_known_mutable({}, "keys")
False
>>> modifies_known_mutable([], "append")
True
>>> modifies_known_mutable([], "index")
False
>>> modifies_known_mutable("foo", "upper")
False
```

### `ImmutableSandboxedEnvironment`

`class jinja2.sandbox.ImmutableSandboxedEnvironment([options])` works exactly like `SandboxedEnvironment` but does not permit modifications on the builtin mutable objects `list`, `set` and `dict`, using `modifies_known_mutable()`. [004-sandbox.md#api](jinja-raw/004-sandbox.md)

### `SecurityError`

`exception jinja2.sandbox.SecurityError(message=None)` — raised if a template tries to do something insecure while the sandbox is enabled. [004-sandbox.md#api](jinja-raw/004-sandbox.md)

## Operator intercepting

By default Jinja outputs operators directly when compiling, so overriding `SandboxEnvironment.call` does not intercept operator behaviour. Operator special methods are handled by the Python interpreter and may not map to exactly one method. [004-sandbox.md#operator-intercepting](jinja-raw/004-sandbox.md)

The compiler can instead emit a function call. Set `intercepted_binops` / `intercepted_unops` to the symbols you want to intercept; the compiler replaces the symbols with calls to `call_binop()` / `call_unop()`. The default implementations translate symbols into `operator` functions via `binop_table` / `unop_table`. [004-sandbox.md#operator-intercepting](jinja-raw/004-sandbox.md)

Disabling the power (`**`) operator, as shown in the raw docs:

```python
from jinja2.sandbox import SandboxedEnvironment

class MyEnvironment(SandboxedEnvironment):
    intercepted_binops = frozenset(["**"])

    def call_binop(self, context, operator, left, right):
        if operator == "**":
            return self.undefined("The power (**) operator is unavailable.")

        return super().call_binop(self, context, operator, left, right)
```

> [!NOTE]
> The raw page shows this exact body, including the leading `self` passed to `super().call_binop`. The documented signature is `call_binop(context, operator, left, right)`, i.e. six arguments including `self`. The raw source is silent on which form is intended; keep the documented signature. [004-sandbox.md#api](jinja-raw/004-sandbox.md)

## Native Python types (`NativeEnvironment`)

`Environment` renders to strings; `NativeEnvironment` produces a native Python type. This suits Jinja used outside text-file creation, e.g. users defining values that are later passed to a traditional string environment. [005-nativetypes.md](jinja-raw/005-nativetypes.md)

```pycon
>>> env = NativeEnvironment()
>>> t = env.from_string('{{ x + y }}')
>>> print(t.render(x=4, y=2), type(t.render(x=4, y=2)))
6 <class 'int'>
```

| Template | Result type |
| --- | --- |
| `'{{ x + y }}'` with `x=4, y=2` | `int` (`6`) |
| `'[{% for item in data %}{{ item + 1 }},{% endfor %}]'` with `data=range(5)` | `list` (`[1, 2, 3, 4, 5]`) |
| `'{{ x }} * {{ y }}'` with `x=4, y=2` | `str` (`4 * 2`) |
| `'{{ x }}'` with `x=Foo(15)` | the `Foo` instance, when it is the only node |

### `render()` rules

`render(*args, **kwargs)` → `Any`. If the result is a single node, its value is returned. Otherwise the nodes are concatenated as strings. If the concatenation can be parsed with `ast.literal_eval()`, the parsed value is returned; otherwise the string is returned. [005-nativetypes.md#api](jinja-raw/005-nativetypes.md)

### Classes

- `class jinja2.nativetypes.NativeEnvironment([options])` — an environment that renders templates to native Python types.
- `class jinja2.nativetypes.NativeTemplate([options])` — template class used by that environment; options mirror the standard environment.

`NativeEnvironment` options: `block_start_string`, `block_end_string`, `variable_start_string`, `variable_end_string`, `comment_start_string`, `comment_end_string`, `line_statement_prefix`, `line_comment_prefix`, `trim_blocks`, `lstrip_blocks`, `newline_sequence`, `keep_trailing_newline`, `extensions`, `optimized`, `undefined`, `finalize`, `autoescape`, `loader`, `cache_size`, `auto_reload`, `bytecode_cache`, `enable_async`. [005-nativetypes.md#api](jinja-raw/005-nativetypes.md)

`NativeTemplate` takes the same list minus `loader`, `cache_size`, `auto_reload` and `bytecode_cache`, plus a leading `source` parameter typed `str | Template`. [005-nativetypes.md#api](jinja-raw/005-nativetypes.md)

### Sandboxed native environment

Combine both behaviours by multiple inheritance; the raw docs give the class with an empty body: [005-nativetypes.md](jinja-raw/005-nativetypes.md)

```python
class SandboxedNativeEnvironment(SandboxedEnvironment, NativeEnvironment):
    pass
```

For the standard environment and its loader/autoescape options see [api.md](api.md); for built-in filters and tests see [filters.md](filters.md) and [tests.md](tests.md).

Extensions add filters, tests, globals, or parser-level tags. They are the supported way to move often-used template code into a reusable class [007-extensions.md#extensions](jinja-raw/007-extensions.md).

## Enabling extensions

Extensions are added to the environment at creation time via the `extensions` parameter, or later with `add_extension()`; both accept a class or an import path [007-extensions.md#adding-extensions](jinja-raw/007-extensions.md).

```python
from jinja2 import Environment

env = Environment(extensions=["jinja2.ext.i18n"])
env.add_extension("jinja2.ext.debug")
```

### `do`, loop controls, debug

`{% do %}` works exactly like `{{ ... }}` but prints nothing; typical use is mutating a list. `break` terminates a loop and `continue` skips to the next iteration, both "exactly like in Python" [006-templates.md#expression-statement](jinja-raw/006-templates.md), [#loop-controls](jinja-raw/006-templates.md).

```html+jinja
{% do navigation.append('a string') %}

{% for user in users %}
    {%- if loop.index is even %}{% continue %}{% endif %}
    {%- if loop.index >= 10 %}{% break %}{% endif %}
    {{ user }}
{% endfor %}
```

`loop.index` starts at 1, `loop.index0` at 0. `{% debug %}` — e.g. `<pre>{% debug %}</pre>` — dumps `'context'`, `'filters'`, and `'tests'` without a debugger [006-templates.md#debug-statement](jinja-raw/006-templates.md).

## i18n extension

**Import name:** `jinja2.ext.i18n`. Combine with gettext or Babel. Enabling it provides a `trans` statement that marks a block as translatable and calls `gettext` [007-extensions.md#i18n-extension](jinja-raw/007-extensions.md).

The application must supply `gettext`, `ngettext`, and optionally `pgettext` and `npgettext`, globally or per render. A `_()` function is added as an alias to `gettext`.

### Environment setup

```python
from jinja2 import Environment

translations = get_gettext_translations()          # app-defined
env = Environment(extensions=["jinja2.ext.i18n"])
env.install_gettext_translations(translations)
```

`get_gettext_translations` is the application's own function; the raw docs only say it "would return the translator for the current configuration, for example by using `gettext.find`". Supported translation objects are `gettext.NullTranslations`, `gettext.GNUTranslations`, and Babel's `Translations` [007-extensions.md#i18n-extension](jinja-raw/007-extensions.md).

### Methods installed by i18n

| Method | Effect |
| --- | --- |
| `install_gettext_translations(translations, newstyle=False)` | Install globally; object must implement `gettext`, `ngettext`, optionally `pgettext`/`npgettext` |
| `install_null_translations(newstyle=False)` | Install no-op gettext functions |
| `install_gettext_callables(gettext, ngettext, newstyle=False, pgettext=None, npgettext=None)` | Install the given callables directly |
| `uninstall_gettext_translations()` | Remove the globally installed translation |
| `extract_translations(source)` | Yield `(lineno, function, message)` tuples from a template node or source |

`pgettext`/`npgettext` were added in 3.0; new-style gettext in 2.5 [007-extensions.md#environment-methods](jinja-raw/007-extensions.md).

> [!TIP]
> Use `install_null_translations()` to prepare an app for i18n before real translations exist.

### Using `trans` blocks

Inside a block only text and simple variable tags are allowed: a name, never attribute access, filters, or other expressions. Bind expressions to names on the `trans` tag [006-templates.md#i18n](jinja-raw/006-templates.md).

```html+jinja
{% trans user=user.username %}Hello, {{ user }}!{% endtrans %}

{% trans book_title=book.title, author=author.name %}
This is {{ book_title }} by {{ author }}
{% endtrans %}
```

Pluralize with `{% pluralize %}`. The first variable decides singular vs plural unless a variable name follows `pluralize`.

```html+jinja
{% trans count=list|length %}
There is {{ count }} {{ name }} object.
{% pluralize %}
There are {{ count }} {{ name }} objects.
{% endtrans %}
```

### Trimming

`trimmed` replaces linebreaks and their surrounding whitespace with a single space and strips leading/trailing whitespace, so the block below becomes `This is %(book_title)s. You should read it!` in the translation file [006-templates.md#i18n](jinja-raw/006-templates.md).

```html+jinja
{% trans trimmed book_title=book.title %}
    This is {{ book_title }}.
    You should read it!
{% endtrans %}
```

Enable trimming globally with the `ext.i18n.trimmed` policy; then `notrimmed` disables it per block (added in 2.10) [007-extensions.md#whitespace-trimming](jinja-raw/007-extensions.md).

### Context strings (`pgettext`)

A string as the first token after `trans` selects the translation context, e.g. `{% trans "fruit" %}apple{% endtrans %}`. Added in 3.1 [006-templates.md#i18n](jinja-raw/006-templates.md).

### Translation functions in expressions

Five functions are available: `_(message)` (alias for `gettext`), `gettext(message)`, `ngettext(singular, plural, n)`, `pgettext(context, message)`, and `npgettext(context, singular, plural, n)`.

```html+jinja
{{ _("Hello, World!") }}
{{ _("Hello, %(user)s!")|format(user=user.username) }}
```

Always pass keyword arguments to `format`: other languages may reorder words.

### New-style gettext

Set `env.newstyle_gettext = True`, or pass `newstyle=True` to the install call. Formatting moves into the call and only named placeholders are allowed [007-extensions.md#new-style-gettext](jinja-raw/007-extensions.md).

```html+jinja
{{ gettext("Hello, World!") }}
{{ gettext("Hello, %(name)s!", name=name) }}
{{ ngettext("%(num)d apple", "%(num)d apples", apples|count) }}
{{ pgettext("greeting", "Hello, World!") }}
{{ npgettext("fruit", "%(num)d apple", "%(num)d apples", apples|count) }}
```

The documented advantages: no separate `|format` step; named placeholders only, so translators cannot make meaningless positional swaps; formatting always applies, so escape raw percent signs as `%%` (`100%%`); the translated string is marked safe and escaping happens as needed, so mark a parameter `|safe` only when it is already escaped. Fully supported by Babel extraction, but "might not work as expected with other extraction tools".

## Writing extensions

Extensions can add custom tags, but this is non-trivial and usually unnecessary [007-extensions.md#writing-extensions](jinja-raw/007-extensions.md).

> [!WARNING]
> The Jinja compiler does **not** validate the node tree you hand it. A malformed AST produces compiler or runtime errors that are horrible to debug. Construct nodes exactly as the API documents.

### `Extension` class

`class jinja2.ext.Extension(environment)` [007-extensions.md#extension](jinja-raw/007-extensions.md)

| Attribute / method | Contract |
| --- | --- |
| `identifier` | The true import name of the extension class; must not be changed |
| `tags` | Set of tag names this extension listens for |
| `preprocess(source, name, filename=None)` | Called before lexing; must return the preprocessed source |
| `filter_stream(stream)` | Receives a `TokenStream`; returns a `TokenStream` or any iterable of `Token`s |
| `parse(parser)` | Called when a `tags` name matched; returns one node or a list of nodes |
| `attr(name, lineno=None)` | Attribute node for this extension on the environment → `ExtensionAttribute` |
| `call_method(name, args=None, kwargs=None, dyn_args=None, dyn_kwargs=None, lineno=None)` | `attr()` + `jinja2.nodes.Call` shortcut |

Three constraints on extension state:

1. Extensions are bound to an environment but must not store environment-specific data on `self`; a copy may be rebound to another environment (overlays).
2. Extensions cannot accept configuration arguments, because they are identified by import name.
3. Configuration lives on the environment via `environment.extend(...)`. Choose non-generic names — `fragment_cache_prefix` is good, `prefix` is terrible.

### `Parser`

`class jinja2.parser.Parser(environment, source, name=None, filename=None, state=None)` [007-extensions.md#parser](jinja-raw/007-extensions.md)

| Member | Signature | Purpose |
| --- | --- | --- |
| `filename` | attribute | Template filename; **not** the load name; `None` for non-file templates |
| `name` | attribute | Template load name |
| `stream` | attribute | Current `TokenStream` |
| `fail` | `fail(msg, lineno=None, exc=TemplateSyntaxError)` | Raise `exc` with message, line, name, filename |
| `free_identifier` | `free_identifier(lineno=None)` | New `InternalName` unavailable to template code |
| `parse_statements` | `parse_statements(end_tokens, drop_needle=False)` | Parse a body until an end token; skips a leading colon |
| `parse_assign_target` | `parse_assign_target(with_tuple=True, name_only=False, extra_end_rules=None, with_namespace=False)` | Parse an assignment target → `NSRef` \| `Name` \| `Tuple` |
| `parse_expression` | `parse_expression(with_condexpr=True)` | Parse any expression |
| `parse_tuple` | `parse_tuple(simplified=False, with_condexpr=True, extra_end_rules=None, explicit_parentheses=False, with_namespace=False)` | Like `parse_expression`, builds `Tuple` when commas appear |

`parse_statements` leaves the matched end token active in the stream unless `drop_needle=True`. `parse_tuple` needs `extra_end_rules` where tuples are undelimited, e.g. `['name:in']` inside `for`.

### Tokens and token streams

`class jinja2.lexer.TokenStream(generator, name, filename)`: `current` (the active `Token`), `eos` (property → `bool`), `push(token)`, `look()` → `Token`, `skip(n=1)`, `next_if(expr)` → `Token | None`, `skip_if(expr)` → `bool`, `next(stream)` (advance and return the old token), `expect(expr)` → `Token` [007-extensions.md#parser](jinja-raw/007-extensions.md).

`class jinja2.lexer.Token(lineno, type, value)` exposes `lineno`, `type` (interned, safe to compare with `is`), `value`, plus `test(expr)` and `test_any(*iterable)`. A token expression is either a type or `'token_type:token_value'`.

`jinja2.lexer.count_newlines(value) -> int` counts newlines in a string; it exists for stream-filtering extensions so line numbers stay accurate.

### AST nodes

Nodes are `class jinja2.nodes.Node`. Fields are positional constructor args; attributes are keyword args. Every node carries `lineno` and `environment`, set automatically after parsing. Four node families exist: `Stmt` (statements), `Expr` (expressions), `Helper` (context-only), and `Template` (outermost wrapper passed to the compiler) [007-extensions.md#ast](jinja-raw/007-extensions.md).

| Method | Signature | Purpose |
| --- | --- | --- |
| `iter_fields` | `iter_fields(exclude=None, only=None)` | Yield `(key, value)` per field |
| `iter_child_nodes` | `iter_child_nodes(exclude=None, only=None)` | Yield direct child nodes |
| `find` | `find(node_type)` | First node of type or `None` |
| `find_all` | `find_all(node_type)` | All nodes of a type or tuple of types |
| `set_ctx` | `set_ctx(ctx)` | Recursively reset load/store context |
| `set_lineno` | `set_lineno(lineno, override=False)` | Set line numbers on node and children |
| `set_environment` | `set_environment(environment)` | Set environment on all nodes |

`Expr` adds `as_const(eval_ctx=None)` (raises `jinja2.nodes.Impossible` when not constant) and `can_assign()`.

| Node | Fields | Meaning |
| --- | --- | --- |
| `Const` | `value` | Any constant with a safe repr |
| `Name` | `name, ctx` | Lookup or store; `ctx` ∈ `store` \| `load` \| `param` |
| `Call` | `node, args, kwargs, dyn_args, dyn_kwargs` | Call; `*args`/`**kwargs` nodes or `None` |
| `Filter` / `Test` | `node, name, args, kwargs, dyn_args, dyn_kwargs` | Apply a filter/test; `node=None` means a filter block |
| `CallBlock` | `call, args, defaults, body` | Unnamed macro passed as `caller` |
| `Output` | `nodes` | Print a list of expressions |
| `InternalName` | `name` | Compiler-only name from `free_identifier()` |
| `ExtensionAttribute` | `identifier, name` | Attribute of an extension, built by `attr()` |
| `ContextReference` / `DerivedContextReference` | — | Current context; the derived form includes locals (2.11) |
| `OverlayScope` | `context, body` | Inject arbitrary variables from a dict into a sub-scope (2.10) |
| `EvalContextModifier` | `options` | Modify eval context, e.g. `Keyword('autoescape', Const(True))` |
| `ScopedEvalContextModifier` | `options, body` | Modify and revert for `body` only |
| `Block` | `name, body, scoped, required` | Block; `required` added in 3.0.0 |

Statements also include `Assign`, `AssignBlock`, `Break`, `Continue`, `ExprStmt`, `For`, `If`, `Macro`, `With`, `Scope`, `Include`, `Import`, `FromImport`, `Extends`, `FilterBlock`. Helpers are `Keyword(key, value)`, `Operand(op, expr)`, and `Pair(key, value)`.

## Minimal working extension: `{% cache %}`

```python
from jinja2 import nodes
from jinja2.ext import Extension


class FragmentCacheExtension(Extension):
    # a set of names that trigger the extension.
    tags = {"cache"}

    def __init__(self, environment):
        super().__init__(environment)
        # add the defaults to the environment
        environment.extend(fragment_cache_prefix="", fragment_cache=None)

    def parse(self, parser):
        # the first token is the token that started the tag; it is a name
        # token with `cache` as value.  We get the line number so that we
        # can give that line number to the nodes we create by hand.
        lineno = next(parser.stream).lineno

        # now we parse a single expression that is used as cache key.
        args = [parser.parse_expression()]

        # if there is a comma, the user provided a timeout.  If not use
        # None as second parameter.
        if parser.stream.skip_if("comma"):
            args.append(parser.parse_expression())
        else:
            args.append(nodes.Const(None))

        # parse the body of the cache block up to `endcache` and drop the
        # needle (which would always be `endcache` in that case)
        body = parser.parse_statements(["name:endcache"], drop_needle=True)

        # return a `CallBlock` node that calls our _cache_support helper
        # method on this extension.
        return nodes.CallBlock(
            self.call_method("_cache_support", args), [], [], body
        ).set_lineno(lineno)

    def _cache_support(self, name, timeout, caller):
        """Helper callback."""
        key = self.environment.fragment_cache_prefix + name

        # try to load the block from the cache; if there is no fragment in
        # the cache, render it and store it in the cache.
        rv = self.environment.fragment_cache.get(key)
        if rv is not None:
            return rv
        rv = caller()
        self.environment.fragment_cache.add(key, rv, timeout)
        return rv
```

Register and configure it on the environment: `env = Environment(extensions=[FragmentCacheExtension])`, then `env.fragment_cache = SimpleCache()` from cachelib [007-extensions.md#cache](jinja-raw/007-extensions.md).

```html+jinja
{% cache 'sidebar', 300 %}
<div class="sidebar">
    ...
</div>
{% endcache %}
```

The reuse shape: take the line number from the name token, parse arguments with `parser.parse_expression()` / `parser.stream.skip_if()`, parse the body with `parse_statements([...], drop_needle=True)`, and return a node built with `self.call_method(...)`. Python-side work lives in a method on the extension and reads config from `self.environment`.

An extension may instead rewrite the token stream, with no block tag. The docs' `InlineGettext` example turns `_(Welcome)` in raw text into `{% trans %}Welcome{% endtrans %}` using `Extension.filter_stream()`, `jinja2.lexer.Token`, and `jinja2.lexer.count_newlines`; it requires the i18n extension and raises `TemplateSyntaxError` for unclosed expressions [007-extensions.md#inline-gettext](jinja-raw/007-extensions.md).

> [!NOTE]
> Inspect any real parse tree with `repr(jinja2.Environment.parse(source))`. The node list is documented as backward compatible across versions but may grow.

**Done when:** you can name the six bundled import paths and the tag each adds, install translations with `install_gettext_translations`, and explain why an extension must keep configuration on the environment rather than on `self`.

Tests are boolean predicates invoked with the `is` operator. They differ from filters — filters transform, tests only answer yes/no. Source: `$SKILL_DIR/references/jinja-raw/006-templates.md`.

```jinja
{% if variable is defined %}
    value of variable: {{ variable }}
{% else %}
    variable is not defined
{% endif %}
```

### Optional-feature guards

`filter` and `test` let a template degrade when an extension may be absent (both added 3.0).

```jinja
{% if 'markdown' is filter %}
    {{ value | markdown }}
{% else %}
    {{ value }}
{% endif %}
```

## Global functions

The globals section lists exactly these six names as available in the global scope by default (lines 2125–2239). Registering your own is covered in [api](api.md) (`Environment.globals`).

### `range([start,] stop[, step])`

Returns a list holding an arithmetic progression of integers. `range(i, j)` yields `[i, i+1, …, j-1]`; `start` defaults to `0`; `step` is the increment or decrement. The end point is omitted, so `range(4)` and `range(0, 4, 1)` both give `[0, 1, 2, 3]` — exactly the valid indices of a 4-element list.

Primary use is repeating a template block a computed number of times.

```html+jinja
<ul>
{% for user in users %}
    <li>{{ user.username }}</li>
{% endfor %}
{% for number in range(10 - users|count) %}
    <li class="empty"><span>...</span></li>
{% endfor %}
</ul>
```

### `lipsum(n=5, html=True, min=20, max=100)`

Generates lorem ipsum for the template. Defaults: five paragraphs of HTML, each between 20 and 100 words. With `html=False` regular text is returned. Intended for layout testing, not production text.

### `dict(**items)`

Convenient alternative to dict literals: `{'foo': 'bar'}` is the same as `dict(foo='bar')`.

### `cycler(*items)`

Cycles through values by yielding them one at a time, restarting after the end. Similar to `loop.cycle`, but usable outside loops or across multiple loops — that is the reason to prefer it. Each positional argument is yielded in the order given for each cycle. Added in 2.1.

```html+jinja
{% set row_class = cycler("odd", "even") %}
<ul class="browser">
{% for folder in folders %}
  <li class="folder {{ row_class.next() }}">{{ folder }}
{% endfor %}
{% for file in files %}
  <li class="file {{ row_class.next() }}">{{ file }}
{% endfor %}
</ul>
```

Members: `current` (property — the item a subsequent `next()` returns), `next()` (return the current item, then advance `current`), `reset()` (reset `current` to the first item).

### `joiner(sep=',')`

A tiny helper to "join" multiple sections. A joiner is passed a separator string and returns it every time it is called, except the first time, when it returns an empty string. Added in 2.1.

```html+jinja
{% set pipe = joiner("|") %}
{% if categories %} {{ pipe() }}
    Categories: {{ categories|join(", ") }}
{% endif %}
{% if author %} {{ pipe() }}
    Author: {{ author() }}
{% endif %}
{% if can_edit %} {{ pipe() }}
    <a href="?action=edit">Edit</a>
{% endif %}
```

### `namespace(...)`

Creates a new container that allows attribute assignment with the `{% set %}` tag: `{% set ns = namespace() %}` then `{% set ns.foo = 'bar' %}`.

Its main purpose is propagating changes across scopes — carrying a value from inside a loop body outward. Initial values may be provided as a dict, as keyword arguments, or both, matching Python's `dict` constructor. Added in 2.10. See [language](language.md) for `{% set %}` scoping.

```html+jinja
{% set ns = namespace(found=false) %}
{% for item in items %}
    {% if item.check_something() %}
        {% set ns.found = true %}
    {% endif %}
    * {{ item.title }}
{% endfor %}
Found item having something: {{ ns.found }}
```

> [!NOTE]
> `obj.attr` assignment in the `set` tag is only allowed for namespace objects; assigning an attribute on any other object raises an exception. The raw docs also annotate "Changed in version 3.2: Namespace attributes can be assigned to in multiple assignment" — newer than the 3.1.x docs version pinned above.

## Custom tests

A test is a Python function taking the value on the left of the test as its first argument and returning `True` or `False`. Arguments passed in the template follow the value. `{{ 42 is even }}` is called behind the scenes as `is_even(42)`. Write a function taking at least a `value` argument, then register it in `Environment.tests` [003-api.md#custom-tests](jinja-raw/003-api.md).

```python
import math
def is_prime(n):
    if n == 2:
        return True

    for i in range(2, int(math.ceil(math.sqrt(n))) + 1):
        if n % i == 0:
            return False

    return True

environment.tests["prime"] = is_prime
```

```jinja
{% if value is prime %}
    {{ value }} is a prime number
{% else %}
    {{ value }} is not a prime number
{% endif %}
```

Decorators tell Jinja to pass extra information. The injected object becomes the first argument, so the tested value moves to second position.

| Decorator | Passes |
| --------- | ------ |
| `pass_environment()` | the `Environment` |
| `pass_eval_context()` | the Evaluation Context |
| `pass_context()` | the current `Context` |

> [!TIP]
> The same three decorators apply to filters and global functions; see [api](api.md) for their `jinja2.*` definitions and version history.

**Done when:** you can name the test that guards an optionally installed filter, and register a custom test that renders correctly inside `{% if value is prime %}`.

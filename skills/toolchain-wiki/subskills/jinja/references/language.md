A template is a plain text file; Jinja generates any text format and needs no specific extension [006-templates.md#synopsis](jinja-raw/006-templates.md). Only syntax and semantics live here — for the builtin catalog see [filters](filters.md) / [tests](tests.md), for `extends`/`blocks`/`include`/`import`/macros see [inheritance](inheritance.md).

> [!NOTE]
> Delimiters and undefined-value behavior are application configuration, so a project may differ from the defaults below [006-templates.md#synopsis](jinja-raw/006-templates.md).

## Quick reference — delimiters and environment switches

| Delimiter | Purpose |
| --- | --- |
| `{{ ... }}` | Expression printed into the output |
| `{% ... %}` | Statement / tag: logic, control flow |
| `{# ... #}` | Comment, excluded from output |
| `line_statement_prefix` | Line statements; **no default prefix** |
| `line_comment_prefix` | Line comments; **no default prefix** |

Delimiters [006-templates.md#synopsis](jinja-raw/006-templates.md); line statements and comments have no default prefix and must be configured on the `Environment` [006-templates.md#line-statements](jinja-raw/006-templates.md).

| `Environment` option | Effect |
| --- | --- |
| `trim_blocks` | Remove the first newline after a template tag |
| `lstrip_blocks` | Strip tabs/spaces from line start to the start of a block |
| `keep_trailing_newline` | Keep the trailing newline Jinja otherwise removes |
| `line_statement_prefix` / `line_comment_prefix` | Enable `#` / `##` line forms |
| `undefined` | Undefined behavior (default: print/iterate → empty string) |

> [!TIP]
> Templates are usually identified by a `templates/` folder rather than an extension. A `.jinja` suffix (e.g. `user.html.jinja`) helps editors, and autoescaping can be keyed off the extension — suffix included [006-templates.md#template-file-extension](jinja-raw/006-templates.md).

## Variables

Template variables come from the context dictionary passed by the application. The braces are the print statement, not part of the variable; inside a tag, use the bare name [006-templates.md#variables](jinja-raw/006-templates.md). Both `{{ foo.bar }}` and `{{ foo['bar'] }}` are valid.

| Expression | Step 1 | Step 2 | Step 3 |
| --- | --- | --- | --- |
| `foo.bar` | `getattr(foo, 'bar')` | `foo['bar']` | undefined |
| `foo['bar']` | `foo['bar']` | `getattr(foo, 'bar')` | undefined |

The two forms differ only in step order, which matters when an object has an item and an attribute with the same name. The `attr()` filter only looks up attributes [006-templates.md#variables](jinja-raw/006-templates.md).

A missing variable gives an undefined value. Default behavior: empty string when printed or iterated, failure for every other operation [006-templates.md#variables](jinja-raw/006-templates.md).

## Filters and tests — usage syntax

Filters transform a value. They follow a pipe (`|`), take optional arguments in parentheses, and chain left-to-right, each output feeding the next [006-templates.md#filters](jinja-raw/006-templates.md).

```html+jinja
{{ name|striptags|title }}   {# title(striptags(name)) #}
{{ listx|join(', ') }}       {# str.join(', ', listx) #}
```

Tests check a variable against a common expression using `is` plus the test name, returning true or false. A single-argument test may drop the parentheses [006-templates.md#tests](jinja-raw/006-templates.md).

```html+jinja
{% if loop.index is divisibleby 3 %}
{% if loop.index is divisibleby(3) %}
```

`name is defined` is the canonical definedness check [006-templates.md#tests](jinja-raw/006-templates.md).

## Comments

`{# ... #}` comments out template text, including embedded tags; it suits debugging and notes to other template authors [006-templates.md#comments](jinja-raw/006-templates.md).

```html+jinja
{# note: commented-out template because we no longer use this {% for user in users %} ... {% endfor %} #}
```

## Whitespace control

Defaults: a single trailing newline is stripped if present; all other whitespace is returned unchanged [006-templates.md#whitespace-control](jinja-raw/006-templates.md).

With `trim_blocks` and `lstrip_blocks` both disabled (the default), block tags on their own lines are removed but a blank line remains, and content spacing is preserved. With both enabled, the block lines disappear entirely [006-templates.md#whitespace-control](jinja-raw/006-templates.md).

```jinja
<div>
    {% if True %}
        yay
    {% endif %}
</div>
```

Default output: `<div>`, blank line, `        yay`, blank line, `</div>`. Fully trimmed output: `<div>`, `        yay`, `</div>` on consecutive lines.

| Marker | Meaning |
| --- | --- |
| `{%+ if ... %}` | Disable `lstrip_blocks` for this tag |
| `{% if ... +%}` | Disable `trim_blocks` for this tag |
| `{%- x -%}` / `{{- x -}}` / `{#- x -#}` | Strip whitespace before and after the tag, expression or comment |

Adding `-` inside a block, comment or expression delimits manual stripping. `{% for item in seq -%} … {%- endfor %}` yields all elements with no whitespace between them — a list `1`–`9` renders as `123456789` [006-templates.md#whitespace-control](jinja-raw/006-templates.md).

> [!WARNING]
> Never put whitespace between the tag and the minus sign. `{%- if foo -%}...{% endif %}` is valid; `{% - if foo - %}...{% endif %}` is not [006-templates.md#whitespace-control](jinja-raw/006-templates.md).

Line statements strip leading whitespace automatically, up to the start of the line [006-templates.md#whitespace-control](jinja-raw/006-templates.md).

## Escaping

To emit a literal `{{`, print it as a string; for larger sections mark the region `raw` [006-templates.md#escaping](jinja-raw/006-templates.md).

```html+jinja
{{ '{{' }}
{% raw %}<li>{{ item }}</li>{% endraw %}
```

> [!NOTE]
> A minus sign at the end of `{% raw -%}` cleans all spaces and newlines preceding the first character of the raw data [006-templates.md#escaping](jinja-raw/006-templates.md).

## Line statements

Line statements require an application-configured prefix; the docs assume `#`. A prefixed line equals the same `{% ... %}` tag [006-templates.md#line-statements](jinja-raw/006-templates.md).

```html+jinja
<ul>
# for item in seq
    <li>{{ item }}</li>     ## this comment is ignored
# endfor
</ul>
```

The prefix may appear anywhere on the line as long as no text precedes it. Block-opening statements (`for`, `if`, `elif`, …) may end with a colon for readability. Statements span multiple lines while parentheses, braces or brackets stay open [006-templates.md#line-statements](jinja-raw/006-templates.md).

Since Jinja 2.2 line comments exist: with prefix `##`, everything from `##` to end of line is ignored, excluding the newline [006-templates.md#line-statements](jinja-raw/006-templates.md).

## Control structures

Control structures — conditionals, for-loops, macros, blocks — appear inside `{% ... %}` in the default syntax [006-templates.md#list-of-control-structures](jinja-raw/006-templates.md).

### For

Iterate a sequence, or unpack mapping items [006-templates.md#for](jinja-raw/006-templates.md).

```html+jinja
{% for user in users %}<li>{{ user.username|e }}</li>{% endfor %}
{% for key, value in my_dict.items() %}<dt>{{ key|e }}</dt>{% endfor %}
```

> [!TIP]
> Dict order is not guaranteed to be what you want to display. Pipe through `|dictsort` when order matters [006-templates.md#for](jinja-raw/006-templates.md).

| Loop variable | Description |
| --- | --- |
| `loop.index` / `loop.index0` | Current iteration, 1-indexed / 0-indexed |
| `loop.revindex` / `loop.revindex0` | Iterations from the end, 1- / 0-indexed |
| `loop.first` / `loop.last` | True on first / last iteration |
| `loop.length` | Number of items in the sequence |
| `loop.cycle` | Helper cycling between a list of values |
| `loop.depth` / `loop.depth0` | Recursion depth, starting at level 1 / 0 |
| `loop.previtem` / `loop.nextitem` | Neighbour item; undefined on first / last |
| `loop.changed(*val)` | True if called with a different value, or not called at all |

Table from [006-templates.md#for](jinja-raw/006-templates.md). `loop.cycle` is used as `class="{{ loop.cycle('odd', 'even') }}"`; since Jinja 2.1 an extra loop-unbound `cycle` global also exists — see the global functions catalog.

Jinja has no `break` or `continue`. Filter the sequence during iteration instead; `loop` then counts only the rendered items [006-templates.md#for](jinja-raw/006-templates.md).

```html+jinja
{% for user in users if not user.hidden %}{{ user.username|e }}{% endfor %}
```

An `else` block renders when no iteration took place — the sequence was empty or filtering removed every item [006-templates.md#for](jinja-raw/006-templates.md).

```html+jinja
{% for user in users %}{{ user.username|e }}{% else %}<em>no users found</em>{% endfor %}
```

Because Jinja loops cannot `break`, `else` was given slightly different behavior than Python's loop `else` [006-templates.md#for](jinja-raw/006-templates.md).

Recursive loops add the `recursive` modifier and call `loop` with the new iterable [006-templates.md#for](jinja-raw/006-templates.md).

```html+jinja
{%- for item in sitemap recursive %}
    {{ item.title }}{%- if item.children -%}{{ loop(item.children) }}{%- endif %}
{%- endfor %}
```

`loop` always refers to the innermost loop. To recurse from an outer scope, rebind it with `{% set outer_loop = loop %}` after that loop, then call `{{ outer_loop(...) }}` [006-templates.md#for](jinja-raw/006-templates.md).

> [!WARNING]
> Assignments inside a loop are cleared at the end of each iteration and cannot outlive the loop scope. Older Jinja versions had a bug that made it look like they could; that behavior is unsupported. Use `loop`, the `else` block, or a `namespace` object instead [006-templates.md#for](jinja-raw/006-templates.md).

### If

The simplest `if` tests whether a variable is defined, not empty, and not false. `elif` and `else` work like Python and accept complex expressions [006-templates.md#if](jinja-raw/006-templates.md).

```html+jinja
{% if users %}{% for user in users %}<li>{{ user.username|e }}</li>{% endfor %}{% endif %}
{% if kenny.sick %}Sick.{% elif kenny.dead %}Dead.{% else %}Okay.{% endif %}
```

`if` also works as an inline expression and as a loop filter [006-templates.md#if](jinja-raw/006-templates.md). Unlike blocks, macros and loops, `if` does not introduce a scope [006-templates.md#assignments](jinja-raw/006-templates.md).

### Filter blocks

A `filter` section applies regular filters to a whole block of template data; argument-taking filters are called the same way, e.g. `{% filter center(100) %}` [006-templates.md#filters](jinja-raw/006-templates.md).

```html+jinja
{% filter upper %}This text becomes uppercase{% endfilter %}
```

### Assignments

`set` assigns values and supports multiple targets. Top-level assignments — outside blocks, macros or loops — are exported from the template and importable by other templates, like top-level macros [006-templates.md#assignments](jinja-raw/006-templates.md).

```html+jinja
{% set navigation = [('index.html', 'Index'), ('about.html', 'About')] %}
{% set key, value = call_something() %}
```

> [!WARNING]
> You cannot set a variable inside a block or loop and see it outside. Below, `iterated` stays `false` because the `set` in the loop is scoped to it [006-templates.md#assignments](jinja-raw/006-templates.md):
>
> ```html+jinja
> {% set iterated = false %}
> {% for item in seq %}{{ item }}{% set iterated = true %}{% endfor %}
> {% if not iterated %} did not iterate {% endif %}
> ```

Use the loop `else` block or the `loop` variable instead; no Jinja syntax makes that snippet propagate [006-templates.md#assignments](jinja-raw/006-templates.md).

Since 2.10, `namespace` objects propagate changes across scopes [006-templates.md#assignments](jinja-raw/006-templates.md).

```html+jinja
{% set ns = namespace(found=false) %}
{% for item in items %}
    {% if item.check_something() %}{% set ns.found = true %}{% endif %}
{% endfor %}
Found item having something: {{ ns.found }}
```

`obj.attr` notation in `set` is allowed **only** for namespace objects; assigning an attribute on any other object raises an exception [006-templates.md#assignments](jinja-raw/006-templates.md).

Block assignment (added in 2.8) captures everything up to `{% endset %}` into a variable — useful because Jinja has no triple-quoted strings. Filters on the variable name apply to the captured content (supported since 2.10), e.g. `{% set reply | wordwrap %}` [006-templates.md#block-assignments](jinja-raw/006-templates.md).

```jinja
{% set navigation %}
    <li><a href="/">Index</a>
{% endset %}
```

## Expressions

Expressions work much like regular Python [006-templates.md#expressions](jinja-raw/006-templates.md).

### Literals

| Literal | Form | Notes |
| --- | --- | --- |
| String | `"Hello World"` | Single or double quotes |
| Integer | `42` / `123_456` | `_` separates digit groups |
| Float | `42.23` / `42.1e2` / `123_456.789` | `e` exponent; `_` not allowed in exponent |
| List | `['list', 'of', 'objects']` | Mutable, iterable |
| Tuple | `('tuple', 'of', 'values')` | Immutable; 1-tuple needs a trailing comma |
| Dict | `{'dict': 'of', 'key': 'and', 'value': 'pairs'}` | Keys unique; rarely used in templates |
| Boolean | `true` / `false` | Lowercase |

Literals and the tuple comma rule [006-templates.md#literals](jinja-raw/006-templates.md). Dicts are rare in templates; one valid case is the `xmlattr()` filter [006-templates.md#literals](jinja-raw/006-templates.md).

> [!NOTE]
> `true`, `false` and `none` are lowercase. `True`, `False` and `None` also work now, but Jinja identifiers are lowercase by convention and lowercase is recommended [006-templates.md#literals](jinja-raw/006-templates.md).

### Operator table

| Operator | Kind | Meaning / example |
| --- | --- | --- |
| `+` | Math | Add; also concatenates strings/lists. `{{ 1 + 1 }}` → `2` |
| `-` | Math | Subtract. `{{ 3 - 2 }}` → `1` |
| `/` | Math | Divide, float result. `{{ 1 / 2 }}` → `0.5` |
| `//` | Math | Truncated integer division. `{{ 20 // 7 }}` → `2` |
| `%` | Math | Remainder. `{{ 11 % 7 }}` → `4` |
| `*` | Math | Multiply; repeats strings. `{{ '=' * 80 }}` |
| `**` | Math | Power. `{{ 2**3 }}` → `8` |
| `==` `!=` | Comparison | Equality / inequality |
| `>` `>=` `<` `<=` | Comparison | Ordering |
| `and` | Logic | `x and y` → `x` if `x` is false, else `y` |
| `or` | Logic | `x or y` → `x` if `x` is true, else `y` |
| `not` | Logic | `not x` → `True` if `x` is false, else `False` |
| `(expr)` | Grouping | Evaluation order and readability |
| `in` | Other | Containment: `{{ 1 in [1, 2, 3] }}` |
| `is` | Other | Perform a test |
| `\|` | Other | Apply a filter |
| `~` | Other | Stringify and concatenate operands |
| `()` | Other | Call a callable with positional/keyword args |
| `.` / `[]` | Other | Attribute access (see Variables) |

From [006-templates.md#math](jinja-raw/006-templates.md), [#comparisons](jinja-raw/006-templates.md), [#logic](jinja-raw/006-templates.md), [#other-operators](jinja-raw/006-templates.md).

Prefer `~` over `+` for string concatenation; calls accept positional and keyword arguments like Python [006-templates.md#other-operators](jinja-raw/006-templates.md).

```html+jinja
{{ "Hello " ~ name ~ "!" }}
{{ post.render(user, full=true) }}
```

> [!WARNING]
> Chained power is evaluated **left to right** in Jinja, unlike Python. `{{ 3**3**3 }}` is `(3**3)**3`, not `3**(3**3)`. Use parentheses; the behavior may change in a future release [006-templates.md#math](jinja-raw/006-templates.md).

`and` / `or` return one of their operands, not necessarily a boolean. In boolean context `and` is true when both operands are truthy, `or` when at least one is [006-templates.md#logic](jinja-raw/006-templates.md).

> [!TIP]
> Negate `is` and `in` with their infix forms: `foo is not bar` and `foo not in bar`. All other negations need prefix notation with parentheses: `not (foo and bar)` [006-templates.md#logic](jinja-raw/006-templates.md).

### If expression

Inline conditional syntax is `<do something> if <something is true> else <do something else>` [006-templates.md#if-expression](jinja-raw/006-templates.md).

```html+jinja
{% extends layout_template if layout_template is defined else 'default.html' %}
```

The `else` part is optional. Without it, the else branch implicitly evaluates to an `Undefined` object, regardless of the environment's `undefined` setting [006-templates.md#if-expression](jinja-raw/006-templates.md).

```jinja
{{ "[{}]".format(page.title) if page.title }}
```

### Python methods

Methods on a variable's type are callable, and the return value becomes the expression's value [006-templates.md#python-methods](jinja-raw/006-templates.md).

```text
{{ page.title.capitalize() }}
{{ f.bar(value) }}
{{ "Hello, %s!" % name }}
{{ "Hello, {}!".format(name) }}
```

Operator methods work too, e.g. `%` for printf-style strings, but `.format` is preferred for that case [006-templates.md#python-methods](jinja-raw/006-templates.md).

## HTML escaping

Two approaches exist: escape each variable manually, or escape everything by default. Jinja supports both; which one is active depends on the application, and the default configuration is **no automatic escaping** [006-templates.md#html-escaping](jinja-raw/006-templates.md).

Reasons for that default: escaping known-safe values (numbers, booleans) is a performance hit, and safety information is fragile, so coercing safe with unsafe values can produce double-escaped HTML [006-templates.md#html-escaping](jinja-raw/006-templates.md).

With manual escaping, escaping is **your** responsibility. If a variable may contain `>`, `<`, `&` or `"`, escape it unless it holds well-formed trusted HTML — pipe it through `|e` [006-templates.md#working-with-manual-escaping](jinja-raw/006-templates.md).

```html+jinja
{{ user.username|e }}
```

With autoescaping on, everything is escaped except values explicitly marked safe. Safe marking comes from the context dictionary via `markupsafe.Markup`, or in the template via `|safe`. Jinja functions — macros, `super`, `self.BLOCKNAME` — always return data marked safe [006-templates.md#working-with-automatic-escaping](jinja-raw/006-templates.md).

> [!WARNING]
> - Escaped-but-unmarked values get escaped again: autoescaping produces double-escaped characters. Wrap such data in `Markup` or use `|safe` [006-templates.md#working-with-automatic-escaping](jinja-raw/006-templates.md).
> - A safety mark can be lost when a string passes through Python code that does not understand it. Track where your data is marked safe [006-templates.md#working-with-automatic-escaping](jinja-raw/006-templates.md).
> - String literals in templates are considered unsafe under autoescaping, because native Python strings are not safe [006-templates.md#working-with-automatic-escaping](jinja-raw/006-templates.md).

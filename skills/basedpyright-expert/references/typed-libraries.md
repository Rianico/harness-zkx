## Library Interface

### py.typed Marker

Include an empty `py.typed` file in your package root. This tells type checkers to use inline annotations.

### Private vs Public Symbols

**Private:**
- Names starting with `_` (but not dunder)
- Imported symbols (unless explicitly re-exported)

**Explicit Re-export:**
```python
from .module import public_func as public_func  # Redundant alias = re-export
from . import submodule  # __init__.py pattern
```

### __all__ for Public Interface

```python
__all__ = ["func_a", "ClassB"]
__all__ += ["func_c"]
__all__.extend(submodule.__all__)
```

Supported operations: `=`, `+=`, `.extend()`, `.append()`, `.remove()`

## Type Completeness

A "type complete" library has all public symbols with known types.

### Known Types

**Classes:**
- All visible methods and variables annotated
- Generic type arguments provided

**Functions:**
- All parameters annotated
- Return type annotated
- Decorators result in known type

**Variables:**
- Explicit type annotation
- Or simple literal assignment

### Exceptions (No Annotation Needed)

- Constants with simple literal values: `MAX_SIZE = 100`
- Enum values
- Type aliases
- `self` and `cls` parameters
- `__init__` return type (always `None`)
- Module-level dunder names (`__all__`, `__version__`, etc.)

## Verifying Type Completeness

```bash
basedpyright --verifytypes my_library
basedpyright --verifytypes my_library --verbose
basedpyright --verifytypes my_library --ignoreexternal
basedpyright --verifytypes my_library --outputjson
```

Outputs a "type completeness score" and lists symbols with ambiguous/unknown types.

## Best Practices

### Wide vs Narrow Types

Use the widest type the implementation supports:

```python
# Bad: Too narrow
def process(items: list[str]) -> None: ...

# Good: Accepts list, tuple, etc.
def process(items: Sequence[str]) -> None: ...
```

### Immutable Containers

Prefer immutable containers for parameters:

| Mutable | Immutable | Benefit |
|---------|-----------|---------|
| `list` | `Sequence` | Covariant |
| `dict` | `Mapping` | Covariant |
| `set` | `Container` | Covariant |

```python
# Accepts list[str | int], list[int], Sequence[str], etc.
def process(items: Sequence[str | int]) -> None: ...
```

## Annotating Decorators

### Simple Decorators (Preserve Signature)

```python
_F = TypeVar("_F", bound=Callable[..., Any])

def simple_decorator(_func: _F) -> _F:
    """Called without parentheses: @simple_decorator"""
    ...

def complex_decorator(*, mode: str) -> Callable[[_F], _F]:
    """Called with arguments: @complex_decorator(mode="easy")"""
    ...
```

### Signature-Mutating Decorators

Use `ParamSpec` and `Concatenate` (Python 3.10+). Complex mutations may require erasing the signature.

## Generic Classes and Functions

```python
_T = TypeVar("_T")  # Private by convention

def identity(x: _T) -> _T:
    return x

class Container(Generic[_T]):
    def __init__(self, value: _T) -> None:
        self.value = value
```

## Type Aliases

```python
# Simple
FamilyPet = Cat | Dog

# Generic
ListOrTuple = list[_T] | tuple[_T, ...]

# Recursive
TreeNode = LeafNode | list["TreeNode"]

# Explicit (PEP 613)
StrOrInt: TypeAlias = str | int
```

## Older Python Compatibility

### Quoted Annotations

```python
def get_config(self) -> "OrderedDict[str, str]":
    return self._config
```

### Type Comments

```python
def send_message(self, name, length):
    # type: (str, int) -> None
    ...
```

### typing_extensions

Import new typing features from `typing_extensions` for older Python versions.

### TYPE_CHECKING

```python
from typing import TYPE_CHECKING

if TYPE_CHECKING:
    from expensive_module import ExpensiveType
```

## Type Narrowing

Basedpyright tracks types through code flow. When a symbol is assigned a new value, its type is narrowed.

```python
def func(val: float | str | complex, test: bool):
    reveal_type(val)  # float | str | complex

    val = 3  # Narrowed to int
    reveal_type(val)  # int

    if test:
        val = "hi"  # Narrowed to str
        reveal_type(val)  # str

    reveal_type(val)  # int | str
```

## Supported Expressions for Narrowing

- `<ident>` (identifier)
- `<expr>.<member>` (member access)
- `<ident> := <expr>` (walrus operator)
- `<expr>[<int>]` (integer subscript)
- `<expr>[<str>]` (string subscript)

Examples:
- `my_var`
- `employee.name`
- `a.b.c.d`
- `args[3]`
- `kwargs["bar"]`

## Type Guards

### Supported Guard Expressions

| Expression | Narrowing |
|------------|-----------|
| `x is None` / `x is not None` | None check |
| `x == None` / `x != None` | None check |
| `x is ...` / `x is not ...` | Ellipsis check |
| `type(x) is T` / `type(x) == T` | Exact type check |
| `isinstance(x, T)` | Instance check |
| `issubclass(x, T)` | Subclass check |
| `x is L` / `x == L` (L is literal) | Literal check |
| `x in y` / `x not in y` (y is container) | Membership check |
| `bool(x)` / `x` (truthy/falsey) | Truthiness check |
| `f(x)` (user-defined type guard) | Custom guard |

Source: [basedpyright-expert-raw/013-type-concepts-advanced.md](basedpyright-expert-raw/013-type-concepts-advanced.md)

### Positive and Negative Narrowing

Some guards narrow in both branches:

```python
def func1(val: Foo | Bar):
    if isinstance(val, Bar):
        reveal_type(val)  # Bar
    else:
        reveal_type(val)  # Foo
```

Some guards narrow only in the positive branch:

```python
def func2(val: float | None):
    if val:
        reveal_type(val)  # float
    else:
        reveal_type(val)  # float | None (could be 0.0 or None)
```

## Aliased Conditional Expressions

Store a guard in a variable for reuse:

```python
def func(x: str | None):
    is_str = x is not None

    if is_str:
        reveal_type(x)  # str
    else:
        reveal_type(x)  # None
```

**Limitations:**
- Target expression must be a simple identifier (not `x[0]` or `x.y`)
- Target expression must not be reassigned elsewhere
- The aliased variable must be assigned only once

## Narrowing for Implied Else

Basedpyright detects when all cases are exhausted:

```python
from enum import Enum

class Color(Enum):
    RED = 1
    BLUE = 2

def func(color: Color) -> str:
    if color == Color.RED:
        return "red"
    elif color == Color.BLUE:
        return "blue"
    # No else needed - all cases covered

# Adding GREEN = 3 would cause an error
```

Works for unions and enums. Requires:
- Declared type (explicit annotation)
- Simple names (not member/index expressions)

## Narrowing Any

`Any` is NOT narrowed except for:
- `isinstance` and `issubclass` guards
- Class pattern matching
- User-defined type guards

```python
a: Any = 3
reveal_type(a)  # Any

a = "hi"
reveal_type(a)  # Any (not narrowed by assignment)
```

## Captured Variables

Narrowed types are preserved in nested functions/lambdas if the variable is not modified:

```python
def func(val: int | None):
    if val is not None:
        def inner():
            reveal_type(val)  # int
        inner()
```

## Value-Constrained TypeVars

TypeVars can be constrained to specific types:

```python
_StrOrFloat = TypeVar("_StrOrFloat", str, float)

def add(a: _StrOrFloat, b: _StrOrFloat) -> _StrOrFloat:
    return a + b

v1 = add("hi", "there")  # str
v2 = add(1.3, 2.4)       # float
v3 = add(1.3, "hi")      # Error: inconsistent types
```

## Conditional Types

When checking a function with constrained TypeVars, basedpyright tracks "conditional" types:

```python
def add_one(value: _StrOrFloat) -> _StrOrFloat:
    if isinstance(value, str):
        sum = value + "1"
    else:
        sum = value + 1

    reveal_type(sum)  # str* | float* (conditional)
    return sum
```

The `*` indicates the type depends on the TypeVar binding.

## Overloads

### Resolution Algorithm

1. Filter by arity (number of arguments) and keyword matching
2. Filter by argument type compatibility
3. If one remains, it wins
4. If multiple remain, first wins (with exceptions for `*args` and `Any`)
5. If none match, expand union types and retry
6. If still none, error

### Any Handling with Multiple Overloads

When `Any` matches multiple overloads, return types are coalesced:

```python
@overload
def func1(x: int) -> int: ...
@overload
def func1(x: str) -> float: ...

def func2(val: Any):
    reveal_type(func1(val))  # float (supertype of int and float)
```

## Class and Instance Variables

### Three Categories

| Category | Declaration | Access via Class | Access via Instance |
|----------|-------------|------------------|---------------------|
| Pure class variable | `ClassVar[int]` | Yes | Yes (read-only) |
| Regular class variable | `x: int = 0` | Yes | Yes (can be shadowed) |
| Pure instance variable | `self.x: int` in method | No | Yes |

### Pure Class Variables

```python
class A:
    x: ClassVar[int] = 0

    def method(self):
        self.x = 1  # Error: cannot overwrite class variable

A.x = 1  # OK
a.x = 2  # Error: cannot overwrite class variable
```

### Regular Class Variables

```python
class A:
    x: int = 0  # Regular class variable

    def instance_method(self):
        self.x = 1  # Creates instance variable

A.x = 1     # OK
a.x = 2     # Creates instance variable
```

### Pure Instance Variables

```python
class A:
    def __init__(self):
        self.x: int = 0  # Pure instance variable

print(A.x)  # Error: 'x' is not a class variable
print(A().x)  # OK
```

### Inheritance

Variables are inherited from parent classes. The declared type is retained:

```python
class Parent:
    x: object

class Child(Parent):
    x = 3

reveal_type(Parent.x)  # object
reveal_type(Child.x)   # object (declared type retained)
```

If neither parent nor child declares the type, it's inferred:

```python
class Parent:
    x = object()

class Child(Parent):
    x = 3

reveal_type(Parent.x)  # object
reveal_type(Child.x)   # int
```

## Type Variable Scoping

TypeVars are bound to the scope where they appear:

```python
T = TypeVar("T")

def func(a: T) -> T:
    b: T = a  # T refers to T@func
    return b
```

### Return Callable Binding

If a TypeVar appears only in a return `Callable`, it binds to that Callable:

```python
def func1() -> Callable[[T], T]:  # T binds to the Callable
    ...

def func2(a: T) -> Callable[[T], T]:  # T binds to func2
    ...
```

## Literal Math Inference

Operations on literal types produce new literal types:

```python
def func(x: Literal[1, 3], y: Literal[4, 7]):
    reveal_type(x + y)  # Literal[5, 8, 7, 10]
    reveal_type("a" + "b")  # Literal["ab"]
```

Limited to 64 subtypes in the result. Disabled in loops and lambdas.

## Static Conditional Evaluation

Basedpyright statically evaluates:

- `sys.version_info <comparison> <tuple>`
- `sys.platform == <string>`
- `typing.TYPE_CHECKING`
- `True` / `False`
- Identifiers defined in `defineConstant`
- `not`, `and`, `or` combinations of the above

Code in always-false branches is not analyzed (except for syntax errors).

## Reachability Analysis

### Non-Type Information

Unreachable code detected without type analysis:
- `return`, `raise`, `continue` followed by code
- `if False:` block
- `if not TYPE_CHECKING:` block

### Type Information

Unreachable code detected via type analysis:
- Function returning `NoReturn` followed by code
- Impossible type checks (`if not isinstance(x, str):` when `x: str`)
- Exhausted literal unions

Reported via `reportUnreachable` rule (hint by default, warning in recommended mode).

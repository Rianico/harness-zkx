## Type Declarations

Type annotations declare the expected type for a symbol. If no annotation is provided, any value can be assigned.

```python
a: float = 3      # OK: int is assignable to float
b: int = 3.4      # Error: float not assignable to int
c: int | float = 3.4  # OK: union type
d: Optional[int] = None  # OK: Optional is union with None
```

## Assignability

Type checking verifies that assigned values are compatible with declared types.

| Source Type | Target Type | Assignable |
|-------------|-------------|------------|
| `int` | `float` | Yes |
| `float` | `int` | No |
| `int` | `int \| None` | Yes |
| `None` | `int \| None` | Yes |
| `list[int]` | `list[int \| None]` | No (invariant) |
| `list[int]` | `Sequence[int \| None]` | Yes (covariant) |

Source: [basedpyright-expert-raw/007-type-concepts.md](basedpyright-expert-raw/007-type-concepts.md)

## Generic Types and Invariance

Mutable containers (`list`, `dict`, `set`) have invariant type parameters. An exact type match is enforced.

```python
my_list_1: list[int] = [1, 2, 3]
my_list_2: list[int | None] = my_list_1  # Error!
my_list_2.append(None)
# my_list_1 now contains None, violating its type
```

### Solution: Use Immutable Containers

| Mutable Type | Immutable Type |
|--------------|----------------|
| `list` | `Sequence` |
| `dict` | `Mapping` |
| `set` | `Container` |
| (none) | `tuple` |

```python
my_list_1: list[int] = [1, 2, 3]
my_list_2: Sequence[int | None] = my_list_1  # OK
```

## Debugging Types

Use `reveal_type()` to see the inferred type of an expression:

```python
x = 1
reveal_type(x)  # Type of "x" is "Literal[1]"
```

This function is always available and does not need to be imported.

## Unknown vs Any

### Unknown Type

When a type cannot be inferred, basedpyright assigns `Unknown` (a special form of `Any`):

```python
def func(a, b):  # Parameters have Unknown type
    return a + b  # Return type is Unknown
```

`Unknown` allows basedpyright to warn about missing type information via `reportUnknown*` rules.

### Explicit Any

`Any` is explicitly declared. `reportAny` and `reportExplicitAny` can ban `Any` usage.

```python
def foo(bar, baz: Any) -> Any:
    print(bar)   # reportUnknownVariableType if enabled
    print(baz)   # reportAny if enabled
```

## Type Inference

### Single-Assignment Inference

```python
var1 = 3           # int
var2 = "hi"        # str
var3 = list()      # list[Unknown]
var4 = [3, 4]      # list[int]
for var5 in [3, 4]:
    ...            # var5 is int
```

### Multi-Assignment Inference

Types are unioned across assignments:

```python
class Foo:
    def __init__(self):
        self.var1 = ""    # str

    def do_something(self, val: int):
        self.var1 = val   # var1 is now str | int
```

Source: [basedpyright-expert-raw/014-type-inference.md](basedpyright-expert-raw/014-type-inference.md)

## Bidirectional Type Inference

When the LHS has a declared type, it influences the RHS:

```python
var1 = []              # list[Unknown]
var2: list[int] = []   # list[int] - bidirectional resolves ambiguity
var3 = [4]             # list[int]
var4: list[float] = [4]  # list[float] - bidirectional overrides literal
```

## Empty Container Inference

When a variable is assigned an empty container on one path and a non-empty on another, the type is inferred from the non-empty:

```python
if some_condition:
    my_list = []
else:
    my_list = ["a", "b"]

reveal_type(my_list)  # list[str]
```

## Return Type Inference

Return types are inferred from all `return` statements plus an implicit `return None` at the end:

```python
def func1(val: int):
    if val > 3:
        return ""
    elif val < 1:
        return True
    # implicit return None
# Inferred return type: str | bool | None
```

### Never Return Type

If no code path returns, the return type is `Never`:

```python
class Foo:
    def method1(self):
        raise Exception()  # Return type: Never

    @abstractmethod
    def method2(self):
        raise NotImplementedError()  # Return type: Unknown (exception for abstract methods)
```

Source: [basedpyright-expert-raw/014-type-inference.md](basedpyright-expert-raw/014-type-inference.md)

## Never vs NoReturn

`Never` and `NoReturn` mean the same thing. `Never` is preferred because it can be used more generally:

```python
from typing import assert_never

def foo(value: int | str):
    if isinstance(value, int):
        ...
    elif isinstance(value, str):
        ...
    else:
        assert_never(value)  # Error if any type unaccounted for
```

## Parameter Type Inference

### Self and Cls

```python
class Parent:
    def method1(self):  # self is Self@Parent
        return self

    @classmethod
    def method2(cls):  # cls is Type[Self@Parent]
        return cls

class Child(Parent): ...

reveal_type(Child().method1())  # Child
reveal_type(Child.method2())    # Type[Child]
```

### Inherited Parameter Types

If a method overrides a base class method with annotated parameters, types are inherited:

```python
class Parent:
    def method1(self, a: int, b: str) -> float: ...

class Child(Parent):
    def method1(self, a, b):  # a: int, b: str inherited
        return a

reveal_type(Child.method1)  # (self: Child, a: int, b: str) -> int
```

### Default Argument Inference

```python
def func(a, b=0, c=None):
    pass

reveal_type(func)  # (a: Unknown, b: int, c: Unknown | None) -> None
```

## Literal Types

Python 3.8+ supports literal types:

```python
def func1() -> Literal[1, 2, 3]: ...
def func2(mode: Literal["r", "w", "rw"]) -> None: ...
```

Literal types are generally NOT inferred (widened to base type), except for tuples:

```python
var1 = [4]       # list[int], not list[Literal[4]]
var2 = (1, "a")  # tuple[Literal[1], Literal["a"]]
```

## Container Inference Rules

### List Expressions

| Scenario | Without Annotation | With Annotation |
|----------|-------------------|-----------------|
| Empty list | `list[Unknown]` | Uses declared type |
| Same type elements | `list[T]` | Uses declared type |
| Mixed types | `list[Unknown]` (or union if `strictListInference=true`) | Uses declared type |

```python
var1 = []           # list[Unknown]
var2 = [1, 2]       # list[int]
var3 = [1, 3.4]     # list[Unknown] (off) or list[int | float] (strictListInference)
var4: list[float] = [1, 3.4]  # list[float]
```

### Set Expressions

Same rules as lists, controlled by `strictSetInference`.

### Dictionary Expressions

Same rules as lists, controlled by `strictDictionaryInference`.

```python
var1 = {}                     # dict[Unknown, Unknown]
var2 = {1: ""}               # dict[int, str]
var3 = {"a": 3, "b": 3.4}    # dict[str, Unknown] (off) or dict[str, int | float] (strict)
```

## Lambda Inference

Lambda parameters must be inferred from context:

```python
var1 = lambda a, b: a + b  # (a: Unknown, b: Unknown) -> Unknown

def float_sort(list: list[float], comp: Callable[[float, float], bool]): ...

# Types inferred from callback signature
float_sort([2, 1.3], lambda a, b: a < b)  # a and b are float
```

## Strict Inference Flags

| Flag | Effect |
|------|--------|
| `strictListInference` | Union element types instead of Unknown |
| `strictSetInference` | Union element types instead of Unknown |
| `strictDictionaryInference` | Union key/value types instead of Unknown |

Enabled by default in `strict`, `recommended`, and `all` modes.

## Import Resolution Order

For absolute (non-relative) imports, pyright searches in this order:

1. **stubPath** directory (config setting, default "./typings")
2. **Workspace code**
   - Root directory of execution environment
   - Extra paths from config
   - `src/` directory (if no execution environment configured)
3. **Installed packages**
   - Stub packages (PEP 561, `-stubs` suffix)
   - Inline stubs (`.pyi` files in package)
   - `py.typed` packages (inline type annotations)
   - Library code (if `useLibraryCodeForTypes=true`)
4. **Stdlib typeshed** stubs
5. **Third-party typeshed** stubs
6. **Same directory** as importing file (and parent directories within workspace)

## Configuring Python Environment

Pyright determines the Python environment in priority order:

1. `venv` + `venvPath` (discouraged in basedpyright)
2. `python.pythonPath` setting
3. `.venv` folder at project root (basedpyright default)
4. System Python (`python` in shell)

### .venv Auto-Detection

Basedpyright automatically detects `.venv` at project root if neither `pythonPath` nor `venvPath`/`venv` are set.

## Editable Installs

Static analysis tools cannot use import hooks (they require code execution). Configure editable installs to use `.pth` files instead.

### setuptools

- [compat mode](https://setuptools.pypa.io/en/latest/userguide/development_mode.html#legacy-behavior)
- [strict mode](https://setuptools.pypa.io/en/latest/userguide/development_mode.html#strict-editable-installs)

### uv

Uses `.pth` files by default.

### Hatchling

Uses `.pth` files by default. Only uses import hooks if `dev-mode-exact=true`.

### PDM

Uses `.pth` files by default. Only uses import hooks if `editable-backend="editables"`.

## Import Statement Side Effects

### Loader Side Effects (Not Modeled)

Pyright does not model side effects of the import loader:

```python
import a.b  # Loads a.b module

import a  # Does NOT provide access to a.b
# Pyright treats this as an error if you try to use a.b
```

### Safe Implicit Module Loads

Pyright models two safe patterns:

1. `import a.b.c` loads `a`, `a.b`, and `a.b.c`
2. `from . import a` in `__init__.py` loads submodule `a`

## Type Stub Files

### Importance

Pyright prefers `.pyi` files over `.py` files. Without stubs:
- Symbols are typed as `Unknown`
- Wildcard imports don't populate namespace

### Generating Type Stubs

**From IDE:**
1. Enable `reportMissingTypeStubs`
2. Hover over missing stub error
3. Click "Quick Fix" > "Create Type Stub For XXX"

**From CLI:**
```bash
basedpyright --createstub django
```

### Cleaning Up Generated Stubs

Generated stubs are a first draft. Common cleanup needed:

1. **Re-exports removed** -- Add back imports meant for re-export
2. **try/except removed** -- Manually add back necessary imports
3. **Untyped decorators** -- Add TypeVar-based annotations

```python
from typing import Callable, TypeVar

_FuncT = TypeVar("_FuncT", bound=Callable[..., Any])

def my_decorator(*args, **kw) -> Callable[[_FuncT], _FuncT]: ...
```

## Custom Builtins

Some Python environments add extra built-in symbols. Create `__builtins__.pyi` to tell pyright about them:

```python
# __builtins__.pyi
def my_custom_builtin() -> None: ...
```

Place at:
- Project root
- `stubPath` directory (default: "./typings")

## py.typed Packages

For packages with inline type annotations, include a `py.typed` marker file:

```
my_package/
    __init__.py
    module.py
    py.typed  # Empty marker file
```

This tells type checkers to use the inline annotations.

## Common Import Issues

### "Import could not be resolved"

1. Check Python environment: `basedpyright --verbose`
2. Verify `.venv` exists at project root
3. Ensure package is installed in the venv
4. Check `extraPaths` config if using src layout

### "Module has no attribute"

1. Verify the module exports the symbol
2. Check for private import issues (use `import X as X` to re-export)
3. Check `__all__` if using wildcard imports

### "Missing type stub"

1. Install stub package: `pip install types-requests`
2. Generate stub: `basedpyright --createstub package_name`
3. Add to `allowedUntypedLibraries` if acceptable
